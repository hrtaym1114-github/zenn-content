2026年4月14日（日本時間4月15日）、Anthropicが **Claude Code Desktopアプリ** を全面再設計しました。並列セッションを前提とした新UI、サイドチャット（⌘+;）、ドラッグ&ドロップレイアウト、統合エディタ — しかし、ネット上には「Claude Desktop」「Claude Code」「Claude Code Desktop」が入り乱れ、**「で、自分は何をインストールすればいいの？」** と混乱している方も多いはずです。

この記事では、その混乱を最初に整理したうえで、新UIの全機能と実践的な使い方を体系的にまとめます。

## [★重要] 「3つのClaude」をまず整理しよう

最初の混乱ポイントはここです。Anthropicが提供する「デスクトップで動くClaude」は **3種類** あり、それぞれ別物です。

| 名称 | 種別 | 主な用途 | 今回再設計されたか |
|------|------|---------|---------------------|
| **Claude Desktop** | チャットアプリ | 会話・ドキュメント作成・MCPサーバー接続 | ❌（別製品） |
| **Claude Code Desktop** | コーディング用デスクトップアプリ | 並列セッションでのコード生成・リファクタリング | ✅ **これが2026-04-14に再設計された** |
| **Claude Code CLI** | ターミナルコマンド | プラグイン拡張・スクリプト自動化・CI/CD | ❌（CLIは別系統） |

### なぜ混同しやすいのか

Anthropic公式はどちらも「Claude」ブランドで提供しており、インストーラも `claude.ai/download`（Claude Desktop）と `claude.ai/install.sh`（Claude Code Desktop）で似ています。さらに、Claude Desktop上でもMCPを介して開発者向け拡張ができるため「**同じアプリなのでは？**」と誤認しがちです。

:::message alert
**今回（4/14）再設計されたのは「Claude Code Desktop」のみ**です。「Claude Desktop（チャット版）」は同日に別のアップデートを受けていますが、本記事では扱いません。
:::

### コマンド名・起動方法の衝突

| 起動経路 | どのClaudeが立ち上がるか |
|---------|-------------------------|
| Macの Launchpad で「Claude」を検索 | Claude Desktop（チャット版） |
| Macの Launchpad で「Claude Code」を検索 | Claude Code Desktop（新IDE） |
| ターミナルで `claude` | Claude Code CLI |

「Claude」と入力するだけではチャット版が起動するため、**アプリ名で明示的に区別**する必要があります。

## 2025年11月版 vs 2026年4月版 — 何が変わったか

Claude Code Desktopは **2025年11月24日（Claude Opus 4.5と同時）** に初リリースされました。今回（2026年4月14日）は、その約5ヶ月後の **大型UI再設計** です。

| 項目 | 旧版（2025-11） | 新版（2026-04） |
|------|----------------|----------------|
| セッション表示 | タブ形式 | **左サイドバーで一元管理** |
| 並列作業の前提 | git worktree で可能だが操作は散在 | **初めから並列ありきのUI** |
| 横道の質問 | 主セッションを汚す | **サイドチャット（⌘+;）で分離** |
| レイアウト | 固定ペイン | **ドラッグ&ドロップ自由配置** |
| エディタ | 外部エディタ呼び出し | **アプリ内ファイルエディタ統合** |
| プレビュー | 限定的 | **HTML・PDF・ローカルサーバー対応** |
| Diff Viewer | 標準 | **大規模変更対応に再構築** |
| SSH対応 | Linuxのみ | **Mac にも拡張** |
| View モード | なし | **Verbose / Normal / Summary の3種** |
| プラグイン | CLIと差分あり | **CLIと同等（parity）** |
| Routines | なし | **定期実行・イベント駆動の自動化** |

:::message
**要点**: 11月版は「Claude CodeをGUI化した」レベル。4月版は「並列エージェント時代のIDE」として再設計された別物と考えてよいです。
:::

## 前提知識：なぜ「並列セッション前提」の再設計だったのか

Anthropicは公式ブログで次のように述べています。

> 開発者は今や「複数のタスクを同時に走らせ、途中で軌道修正し、差分を見て判断するオーケストレーター」になりつつある。
>
> — [Claude公式ブログ](https://claude.com/blog/claude-code-desktop-redesign)

Claude Opus 4.5以降、エージェントが1タスクを完遂するまで数分〜数十分かかるようになりました。1人の開発者が「リファクタリングを回している間にバグ修正を別ブランチで走らせ、テスト生成も並行する」という働き方が現実的になり、**サイドバーで全セッションを見渡す**必要が生まれたのです。

## Claude Code Desktop のセットアップと起動

### インストール

```bash
curl -fsSL https://claude.ai/install.sh | bash
```

macOSの場合はインストーラ経由でもOKです。Windows・Linuxもサポートされています（Electronベース）。

### 対応プラン

- **Pro**（$22/月〜）
- **Max 5x / Max 20x**（$110〜$220/月）
- **Team / Enterprise**
- **Claude API**

:::message alert
Free プランでは利用できません。また、同じ料金でも **Pro は Max の 1/5 の使用量制限** です（リベシティで「自分だけ$33と表示される」と混乱する方の多くは Max プランを選択しているケース）。
:::

### 主要ショートカット

| キー | 動作 |
|------|------|
| `⌘ + ;` (Ctrl+;) | サイドチャットを開く |
| `⌘ + /` (Ctrl+/) | 全ショートカット一覧を表示 |
| `⌘ + N` | 新規セッション |
| ドラッグ | ペイン（ターミナル/プレビュー/Diff/チャット）を自由配置 |

## [★] 5つの並列セッション活用パターン

並列セッションをどう組むかが新UIの肝です。実践で効果的な5パターンを紹介します。

### パターン1: リファクタリング × テスト生成 × ドキュメント更新

3つのセッションを同時起動し、同じリポジトリの異なるworktreeで作業させます。

```bash
# Claude Code Desktopのサイドバーで「+ New Session」を3回
# それぞれに以下のプロンプトを投げる
Session 1: "src/auth/ をリファクタリング。外部インターフェースは維持"
Session 2: "src/auth/ のテストを vitest で書く。カバレッジ90%以上"
Session 3: "docs/ に新しいauth APIのドキュメントを書く"
```

PRがマージされるとサイドバーから自動アーカイブされるので、見通しが悪くなりません。

### パターン2: 本流タスク × サイドチャットで設計相談

メインセッションで実装を走らせながら、`⌘+;` で **サイドチャット** を開き、アーキテクチャの相談を別コンテキストで行います。

```text
メインセッション: "feature/user-settings を実装中"
サイドチャット:   "このリポジトリでRepositoryパターンは過剰か？"
```

サイドチャットはメインのコンテキストを参照できますが、**メインに逆流しない**ため、本流を汚さずに悩みを整理できます。

### パターン3: 複数リポジトリの並列調査

マルチリポジトリで似たバグを探すときに有効です。

```text
Session 1 (repo-frontend): "認証周りでnullチェック漏れを探して報告"
Session 2 (repo-backend):  "同じ方針でバックエンドも探して"
Session 3 (repo-shared):   "sharedライブラリも同じ観点で"
```

サイドバーの **Project別グループ化** で見通せます。

### パターン4: ローカル実装 × クラウド実行のハイブリッド

Claude Code Desktop はローカル実行・クラウド実行を切り替えられます。

- **ローカル**: トライ&エラーを素早く回したい時
- **クラウド**: 長時間バッチ（数十分かかるリファクタ全体掃除など）

クラウドに投げっぱなしにして、進行中の通知はサイドバーで確認します。

### パターン5: Routines で定期実行を仕込む

2026-04-14の同時発表 **Routines** 機能を使うと、スケジュール/APIコール/GitHubイベントでClaude Codeを自動起動できます。

```yaml
# 例: 毎朝8時にdependabot PRの自動レビュー
name: morning-deps-review
schedule: "0 8 * * *"
repo: my-company/my-app
prompt: "Dependabot PRを確認し、リスクがあればコメント、なければapproveしてmerge"
```

アクティブセッション不要で裏で動くため、**朝出社したらすでに5件PRが片付いている** 状態が作れます。

## [★] 公式ベストプラクティス

Anthropic が推奨する使い方を整理します。

> 各ペインはドラッグ&ドロップで配置できる。レイアウトは自分の作業スタイルに合わせて組み立ててほしい。
>
> — [Claude公式ブログ](https://claude.com/blog/claude-code-desktop-redesign)

### 推奨1: セッションを"小さく・多く"保つ

1セッション=1タスク=1 PR単位に分割。大きなタスクを1セッションに詰め込むとコンテキストが肥大化し、トークンも品質も悪化します。

### 推奨2: View モードをタスクで使い分ける

| 状況 | 推奨モード |
|------|-----------|
| 新しいタスク・学習中 | **Verbose**（全ツール呼び出しを確認） |
| 通常運用 | **Normal** |
| 並列多数を見渡したい | **Summary**（1行要約だけ） |

### 推奨3: サイドチャットは"捨ててよい"質問に使う

サイドチャット内容はメインに逆流しません。つまり「この設計は正しい？」など、**答えは欲しいが決定事項ではない質問** に向いています。逆に、決定事項はメインセッションで確定させないと後で追跡できなくなります。

## [★] やりがちなアンチパターン7選

### 1. 全セッションを同じリポジトリのworktreeにしない

:::message alert
worktree分離しないと、同一ファイルへの同時編集で **コンフリクト地獄** になります。新UIはworktreeを前提に設計されているので、初期設定で必ず `~/.claude-worktrees` を有効化しましょう。
:::

### 2. 並列8セッション以上を同時起動

トークン課金が加速度的に増えます。**同時アクティブは3〜5が実用上限**。それ以上はRoutinesに回すかクラウド実行に。

### 3. サイドチャットに重要な決定を書き込む

サイドチャットの結論はメインに戻りません。設計判断など**残したい情報はメインセッション**で出力させましょう。

### 4. Viewモードを常時Verbose

全ツール呼び出しが流れるためノイズが激しく、並列だと画面が追えなくなります。慣れたらNormal/Summaryへ。

### 5. Claude Desktop（チャット版）と混同してMCP設定を書く

Claude Code Desktop は **CLIの `~/.claude/` 設定を引き継ぎ**ます。Claude Desktop（チャット版）の `claude_desktop_config.json` を書き換えても無効です。

### 6. PR自動アーカイブを知らず「セッションが消えた」と焦る

PR がマージ/クローズされるとサイドバーから自動で消えます。**履歴は "Archived" タブ**に残っているので、右上のフィルターで確認しましょう。

### 7. Routines を対話型タスクに使う

Routinesは **非対話前提**です。「質問してきたら答える」前提のタスクは失敗します。プロンプトを完結させ、判断基準まで含めて書きましょう。

## 並列セッション数の最適値

| 作業内容 | 推奨同時セッション数 | 理由 |
|---------|-------------------|------|
| 初学者・試行錯誤期 | **1〜2** | UIに慣れる段階はコンテキストを絞る |
| 単一プロジェクト内の並列タスク | **3** | リファクタ・テスト・ドキュメント |
| 複数プロジェクト並列調査 | **3〜5** | プロジェクト別グループ化の恩恵が最大 |
| Pro プラン利用時 | **最大3** | 使用量制限に引っかかりやすい |
| Max 20x プラン利用時 | **最大5** | コスト的にも実用的 |

## 関連ツール比較

| ツール | 強み | 弱み | 向いている人 |
|-------|------|------|-------------|
| **Claude Code Desktop** | 並列・視覚的・統合ツール | GUIゆえにスクリプト自動化は苦手 | 複数タスクを視覚的に見たい人 |
| **Claude Code CLI** | スクリプト化・CI統合・軽量 | 並列管理は自前（cmuxなど必要） | 自動化重視・ターミナル派 |
| **Claude Desktop（チャット）** | MCP・ドキュメント対話 | コーディング特化機能なし | 対話主体で開発以外も使う |
| **cmux**（OSS） | CLIを並列管理 | GUIなし | CLIの良さを保ちつつ並列 |

:::message
**使い分け結論**: 並列作業が日常化している → Desktop。スクリプト駆動 → CLI + cmux。両方を適材適所で。
:::

## まとめ

- **要点1**: 今回（2026-04-14）再設計されたのは **Claude Code Desktop のみ**。Claude Desktop（チャット版）とは別物
- **要点2**: 2025-11版が **「CLIをGUI化」** だったのに対し、2026-04版は **「並列エージェント時代のIDE」** として再設計された別物
- **要点3**: サイドチャット（⌘+;）は **メインを汚さない横道の質問** 用。決定事項はメインで
- **要点4**: 並列セッションは **3〜5が実用上限**。それ以上はRoutinesで非対話処理へ
- **要点5**: Viewモード（Verbose/Normal/Summary）とProjectグループ化を使えば、並列多数でも迷子にならない

並列エージェント時代のIDEとして、Claude Code Desktopは「Cursor的な統合IDE」とは違う進化の方向に舵を切りました。**1人で複数タスクを同時に回すオーケストレーター**になる道具として使いこなせば、1日の生産性は文字通り倍増します。
