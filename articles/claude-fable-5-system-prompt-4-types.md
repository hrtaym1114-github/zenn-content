## 「Fable 5のシステムプロンプト」は4つの文脈に分かれる — まず整理しよう

「システムプロンプト」という同じ言葉が、**4つの異なる文脈**で使われています（うち④は「存在しない」が答え）。最初に結論の表を置きます。これさえ押さえれば、タイムラインの混乱はほぼ解けます。

| # | 呼ばれ方 | 実体 | 公式性 | 検証可能性 |
|---|---------|------|--------|-----------|
| ① | 公式 release-notes 版 | Claude.ai（消費者向けチャット）の「コア」システムプロンプト。Anthropicが透明性方針で公開 | **公式** | ◎（一次情報） |
| ② | リーク版 | Claude.aiの「完全版」と**称される**非公式の抽出物 | 非公式 | ✗（検証不能） |
| ③ | Claude Code 版 | CLI/Agent SDK が積む、コーディング特化の別プロンプト | 一部公式 | ○（挙動で確認可） |
| ④ | API 版 | **存在しない**（デフォルトで空。開発者が自分で書く） | — | — |

### なぜ「公式公開」と「リーク」が同時に流れるのか

①と②が混同されているからです。両者は**同じ Claude.ai の構成**を指しつつ、「公式が出した部分版」と「非公式に出回る全文とされるもの」という別の公開物です。

- Anthropic は**慣例として、消費者向けチャット（Claude.ai / iOS / Android）の「コア」システムプロンプトを release-notes で公開**しています。これは Claude 3 系から続く透明性方針で、業界では珍しい開示姿勢です（[参考](https://docs.claude.com/en/release-notes/system-prompts)）。**Fable 5 版も2026年6月9日付で掲載されています。**
- ただし公開されるのはあくまで**「コア」部分**で、ツール定義などがどこまで含まれるかは明示されていません。
- 一方、「Claude.aiの完全版」と**称する**非公式の抽出物が GitHub 等で共有されています（②）。**Anthropicは内容を確認しておらず、第三者は完全性・改変の有無を検証できません。** 公開日・分量・公開者には諸説あります。

:::message alert
「公式が全文を出した」は不正確です。**公式が出しているのは①のコア版**、出回っている**全文と称される抽出物は②の非公式版**（検証不能）。この2つを区別するだけで、ほとんどの誤解は消えます。
:::

### ③④を巻き込んだ「4つ目の混乱」

さらにややこしいのは、**Claude Code（CLIツール）は Claude.ai とは別の独自プロンプトを積んでいる**点です。「Claude.aiのシステムプロンプト」は Claude Code の挙動の**直接の説明にはなりません**（同じモデルの共通挙動を知る参考にはなります）。そしてAPIには**そもそもデフォルトのシステムプロンプトが無い**（④）。「システムプロンプト」という同じ言葉が、文脈ごとに別の対象を指しています。

## 前提知識：そもそもシステムプロンプトとは

システムプロンプトは、モデルが応答を生成する前に**毎回先頭に注入される指示文**です。Claude.aiの場合、現在の日付、Markdownでのコード整形、回答のトーンや拒否の線引きなどが定義されています。

ポイントは「**どの製品で使うかによって、注入されるシステムプロンプトがまったく違う**」こと。Fable 5 という**モデル**は共通でも、それを動かす**製品**で扱いが変わります。Claude.ai には固定のプロンプトが乗り、Claude Code は独自のプロンプトを積み、**API は何も乗らず開発者が自分で書く**。「Fable 5のシステムプロンプト」という言い方自体が、実はあいまいなのです。

## 4種類それぞれの正体と入手先

### ① 公式 release-notes 版（Claude.ai 消費者向け）

- **入手先**: [docs.claude.com/en/release-notes/system-prompts](https://docs.claude.com/en/release-notes/system-prompts)
- **中身**: 日付設定、Markdown整形の推奨、応答スタイル、安全方針の概要など
- **位置づけ**: Anthropicが「コア」システムプロンプトとして公開するもの。ツール定義などがどこまで含まれるかは明示されていない

:::message
※**2026年6月9日付で Fable 5 版が上記ページに掲載済み**です（2026年6月15日時点で確認）。最新の更新状況は公式ページでご確認ください。
:::

### ② リーク版（非公式・検証不能）

- 「Claude.aiの完全版」と称される非公式の抽出物。GitHub等で「system_prompts_leaks」系リポジトリとして共有されている
- **公開日・分量・公開者には諸説あり**（「約12万字」「研究者が公開」等の言説があるが一次情報で確定できない）
- **Anthropic未確認**。完全性・正確性は誰も保証できない

本記事は方針として、**②の中身の解説には踏み込みません**。検証できないソースを一次情報のように二次解説すると、誤情報を広げかねないためです。

### ③ Claude Code 版

- **入手の考え方**: Claude Code は CLI/Agent SDK 独自のプロンプトを積む。コミュニティが各バージョンの構成を継続的に整理している（例: [Piebald-AI/claude-code-system-prompts](https://github.com/Piebald-AI/claude-code-system-prompts)）
- **中身**: ツール使用説明、コードスタイル、応答の冗長度、セキュリティ指示、作業ディレクトリの文脈など
- **Agent SDK の挙動**: デフォルトは**最小プロンプト**。フル版を使うには明示的に指定する

```typescript
// Agent SDK でフルの Claude Code システムプロンプトを使う
const options = {
  systemPrompt: { type: "preset", preset: "claude_code" }
};
```

（出典: [Modifying system prompts - Claude Code Docs](https://code.claude.com/docs/en/agent-sdk/modifying-system-prompts)）

### ④ API 版（デフォルトなし）

- API はデフォルトでシステムプロンプトを**持たない**。開発者が白紙から書く

```python
# API はシステムプロンプトを自分で指定する（デフォルトは空）
import anthropic

client = anthropic.Anthropic()
message = client.messages.create(
    model="claude-fable-5",
    max_tokens=1024,  # 必須パラメータ
    system="あなたは簡潔に答えるアシスタントです。",  # ← 自分で書く部分
    messages=[{"role": "user", "content": "こんにちは"}],
)
```

## Anthropic公式の透明性方針（権威の整理）

なぜそもそも「公式公開」が成立するのか。Anthropicの方針が背景にあります。

> Anthropic has published the system prompts for its latest models ... and plans to make this sort of disclosure a regular thing as it updates and fine-tunes its system prompts.
>
> — [Startup Fortune: Anthropic publishes Claude system prompts](https://startupfortune.com/anthropic-publishes-claude-system-prompts-setting-new-ai-transparency-bar/)

ここから導ける実務的な指針は3つです。

### 指針1: 一次情報は「release-notes」にある
うわさの全文より、公式が継続的に更新する release-notes を起点にする。

### 指針2: 公式版は「部分版」と割り切る
ツール定義などが省かれているのは仕様。網羅性をリーク版に求めず、足りない部分は**実挙動の検証**で補う。

### 指針3: モデルではなく「製品」で考える
「Fable 5のプロンプト」ではなく「**Claude.aiのプロンプト / Claude Codeのプロンプト**」と製品単位で捉えると混乱しない。

## やりがちなアンチパターン7選

### 1. リーク版を「公式」として引用する
:::message alert
②は検証不能。記事やドキュメントで一次情報のように引用すると、誤情報を広げるリスクがある。引用するなら「非公式・未検証」と明記する。
:::

### 2. Claude.aiのプロンプトでClaude Codeの挙動を説明する
①と③は別物。Claude Codeの挙動を語るなら③を見る（①はモデル共通の挙動を知る参考にはなる）。

### 3. APIに「デフォルトのシステムプロンプトがある」と思い込む
④は空。期待した挙動が出ないのは、システムプロンプトを書いていないから、というケースが多い。

### 4. 全文と称する巨大テキストを読み込ませて消費する
検証不能な巨大テキストをそのままコンテキストに入れると、トークンを浪費し、誤った前提を埋め込むことになる。

### 5. 「show your thinking」系の指示を残したまま使う
:::message alert
Fable では「思考過程を応答に書き出して」系の指示が分類器に引っかかり、**旧モデルへのフォールバックが多発**します（**公式の Fable 5 プロンプトガイドに記載**）。既存スキル/プロンプトに残っていないか確認を。
:::

### 6. 細かいルールを大量に書き込む
Fable 5 は指示追従が強化され、短い指示でも制御しやすい。過剰なルールはかえって逆効果になりうる。

### 7. 「なぜ」を書かずに作業だけ指示する
作業内容に加えて**背景・目的**を伝えると追従精度が上がる、という設計指針が報告されている。
