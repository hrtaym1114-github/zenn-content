## この記事で分かること

「アクティブ1Bしかないのに日本語が流暢で、MacBookで221トークン/秒出た」——そんな投稿でバズった **Liquid AI の LFM2.5-8B-A1B**。気になって調べ始めると、最初の壁にぶつかります。

- 「LFM2.5」で検索すると**1月に出た別物の記事**ばかり出てくる
- 「アクティブ1B」「A1B」「reasoning-only」が何を指すのか分からない
- そもそも**普通のMac**で本当にあの速度が出るのか？

この記事を読めば、①「1月のLFM2.5」と「5月のLFM2.5-8B-A1B」を一発で区別でき、②自分のMacで動かす正しいコマンドが分かり、③**ハイプの221-253 tok/sが何のマシンの数字なのか**を実測ベースで判断できるようになります。

:::message
**対象読者**: Apple Silicon Mac でローカルLLMを常用したい人／小型MoEモデルの実力を見極めたい中級者

## 「LFM2.5」は2つある — まず整理しよう

検索結果が噛み合わない最大の原因はこれです。**「LFM2.5」という名前は2系統を指しています。**

| 項目 | LFM2.5 シリーズ（2026-01） | **LFM2.5-8B-A1B（2026-05-28）← 本記事** |
|------|---------------------------|------------------------------------------|
| 形 | 1.2B などの**密モデル**（+ 日本語特化 1.2B-JP） | **ハイブリッドMoE**（総8.3B / アクティブ1.5B） |
| 文脈 | 「軽量オンデバイスLLM」一般 | 5月の新しいMoE・**reasoning対応** |
| 日本語記事 | WEEL / GIGAZINE 等**多数（飽和）** | **実質ほぼゼロ**（特にApple Silicon実測は皆無） |

### 「A1B」「アクティブ1.5B」とは何か

`A1B` は **Active 1B**、つまり「1トークン生成するたびに動くパラメータが約1B級」という意味です。総パラメータは 8.3B ありますが、MoE（Mixture-of-Experts）なので**毎回そのうち一部だけ**が動きます。

:::message alert
ただし**実際のアクティブ数は1.5B**です（公式モデルカード／MarkTechPostの実値）。「A1B」は名付けで、体感は「8Bの賢さに近く、速度は1.5B級」を狙ったモデルだと理解すると正確です。
:::

### 「reasoning-only」= 毎回CoTが前置きされる

LFM2.5-8B-A1B は **reasoning モデル**で、**回答の前に必ず思考過程（chain-of-thought）を出します**。非reasoning版はありません。これは後述しますが、チャット用途では地味に効いてくる仕様です。

---

## 前提知識：なぜ「アクティブ1.5BのMoE」なのか

ローカルLLMで効くのは「賢さ」だけでなく「**1トークンあたり何パラメータ動くか**」です。デコード（文章生成）速度は基本的に**メモリ帯域に律速**され、毎回動くパラメータが少ないほど速くなります。

LFM2.5-8B-A1B は「8.3Bの知識量を持ちつつ、毎回1.5Bしか動かさない」設計で、**省メモリ・高速・オンデバイス**を狙っています。アーキテクチャは24層（18×double-gated LIV畳み込み + 6×GQA）のハイブリッド、コンテキストは **128K**、学習トークンは 38T、語彙は 128,000（日本語など非ラテン系のトークン効率が改善）です。

前世代 **LFM2-8B-A1B（2025-10・非reasoning）** からの公式ベンチの伸びは大きく、IFEval 79.44→**91.84**、MATH500 74.80→**88.76**、非ハルシネーション率 7.46→**63.47** とされています（いずれもLiquid自社ベンチ）。

## セットアップ（検証済みコマンド）

Apple Silicon で動かす経路は主に3つ。**`ollama run maternion/...` のような野良モデル名を打つ前に**、公式ルートを押さえましょう。

### ① Ollama（最も手軽・16GBで余裕）

```bash
# 公式GGUFをHugging Face経由で。Q4_K_Mで約5.2GB
ollama run hf.co/LiquidAI/LFM2.5-8B-A1B-GGUF:Q4_K_M --verbose
```

:::message alert
**Ollama は v0.17.1-rc0 以上が必須**。安定版 v0.17.0 は lfm2moe アーキで `missing tensor 'output_norm.weight'` エラーになります（私の環境は 0.24.0 で問題なし）。`ollama run maternion/lfm2.5` というコミュニティ版もありますが、**Liquid公式ではありません**。
:::

### ② MLX（Apple Silicon公式・Liquidが推奨する経路）

```bash
# 公式の8bit MLXビルド
mlx_lm.generate --model LiquidAI/LFM2.5-8B-A1B-MLX-8bit \
  --prompt "ローカルLLMの利点を3つ教えて" --max-tokens 512 --temp 0.2
```

### ③ llama.cpp（量子化を細かく選びたい人向け）

```bash
llama-cli   -hf LiquidAI/LFM2.5-8B-A1B-GGUF:Q4_K_M   # CLI
llama-server -hf LiquidAI/LFM2.5-8B-A1B-GGUF:Q4_K_M   # APIサーバ
```

公式GGUFの量子化とサイズ（目安）:

| quant | サイズ | 用途 |
|-------|--------|------|
| Q4_0 | 4.84GB | 最小 |
| **Q4_K_M** | **5.16GB** | **16GB機の推奨** |
| Q5_K_M | 6.03GB | 品質寄り |
| Q8_0 | 9.01GB | 高品質 |
| F16 | 16.9GB | フル精度 |

## 実際に動かす — サンプリングとCoTの扱い

チャットテンプレートは ChatML 系で、公式推奨のサンプリングは **temperature 0.2 / top_k 80 / repetition_penalty 1.05** です。

reasoning モデルなので、出力はこうなります（実際の出力を要約）:

```text
<think>
The user asks ... three advantages of running LLM locally ...
（モデルの思考過程。英語で出ることが多い）
</think>
1. コスト削減：自前のサーバーや設備を用意する必要がなく…
2. プライバシー保護：データが外部に送信されないため…
3. カスタマイズの自由度：モデルやパラメータを自由に変更でき…
```

:::message
面白いことに、**思考（CoT）は英語、最終回答は日本語**で出てきました。アプリに組み込むなら `</think>` 以降だけを表示する処理が必要です。
:::

## Apple Siliconで実測してわかった5つのこと

ここが本記事の核です。**Apple M5 / 16GB** で実際に測りました（2026-06-01）。

| 経路 | 量子化 | 生成速度 | ピークメモリ |
|------|--------|---------|-------------|
| Ollama | Q4_K_M (5.2GB) | **84.3 tok/s** | 約5–6GB |
| MLX | 8bit (8.3GB) | **58.3 tok/s** | **9.04GB** |

> プロンプト処理: Ollama 89.6 tok/s。モデルロード約4秒。プロンプトは「ローカルでLLMを動かす利点を、初心者にもわかるように3つ、それぞれ1〜2文で日本語で説明して」。

### 1. 「221-253 tok/s」は高位チップの数字。普通のM5は約1/3

公式は **M5 Max で 253 tok/s**、バズ投稿は **221 tok/s**。一方、**素のM5/16GBでは Q4で約84、MLX-8bitで約58 tok/s** でした。デコードはメモリ帯域律速で、Max系は無印の3〜4倍の帯域があるため、この差はほぼ「帯域差」で説明できます（84×3≒252 が公式値とほぼ一致）。

### 2. それでも「実用」ではある

84 tok/s 出れば、体感は読むより速く、日常のチャット・要約・下書きには十分実用的でした。「信じられない速度」ではないが「ちゃんと使える速度」です。

### 3. 16GBなら Q4_K_M が最適（8bitより速い）

意外にも **Q4(84) > MLX-8bit(58)**。8bitは重い分だけ遅く、ピーク9GBで16GB機をやや圧迫します。**16GB機は Q4_K_M が速度・省メモリの両取り**です。

### 4. 日本語品質は素直に良い

指示（3点・各1〜2文・日本語）を**正確に守り**、内容も自然でした。公式の IFEval 91.84（指示追従）が体感と一致します。

### 5. reasoning-only は実機で要対策

毎回 `<think>` が前置きされるため、短答用途では冗長です。表示制御を前提に組み込みましょう。

## Liquid AI 公式のベストプラクティス

> LFM2.5-8B-A1B は「オンデバイスのパーソナルアシスタント」「ツール呼び出しの連鎖」「複雑な指示の遂行」向けに設計され、ノートPCやスマホ上でプライベートに完結する用途を想定している。
>
> — Liquid AI 公式ブログ / Hugging Face モデルカード（https://www.liquid.ai/blog/lfm2-5-8b-a1b）

### 推奨1: サンプリングは temp 0.2 を起点に

公式推奨は temperature 0.2 / top_k 80 / repetition_penalty 1.05。創造性より**安定した指示追従**に振った設定です。

### 推奨2: 向いている用途・向かない用途を見極める

公式が**非推奨**としているのは「**ヘビーなコーディング**」と「**検索（RAG）なしの知識QA**」。エッジモデルは知識容量が限られハルシネーションが増えるためです。逆にエージェント的なツール連鎖・多言語アシスタントは得意領域です。

### 推奨3: テキスト専用と割り切る

マルチモーダルはありません。画像・音声が要るなら別モデルと組み合わせます。

## やりがちなアンチパターン 7選

### 1. 「221 tok/s 出るはず」と期待する
:::message alert
あの数字は M5 Max 級。無印チップでは1/3前後が現実です。マシンの帯域で決まると理解しておく。
:::

### 2. 「LFM2.5」一般の記事を読んで満足する
1月の密モデル（1.2B系）の話を、5月のMoE（8B-A1B）と混同しがち。**別物**です。

### 3. Ollama を更新せずに起動する
v0.17.0 だと `missing tensor 'output_norm.weight'` で落ちます。v0.17.1-rc0+ へ。

### 4. `maternion/lfm2.5` を「公式」と思い込む
コミュニティ版です。公式は `LiquidAI/LFM2.5-8B-A1B-GGUF`（GGUF）/ `-MLX-8bit`（MLX）。

### 5. 16GB機で安易に8bitを選ぶ
MLX-8bitはピーク約9GB。Q4_K_Mの方が速く軽い。**16GBはQ4が基本**。

### 6. reasoning出力をそのまま表示する
`<think>…</think>` が毎回入る。UIでは除去/折りたたみを。

### 7. ツール呼び出しが効かず原因不明で詰まる
:::message alert
llama.cpp に既知バグ（issue #23838）。LFM2.5の新しいツールコール形式をパーサが弾き、tool使用時に 500 エラーになります。通常チャットは正常。修正PR #23856 が出ているので、**ツール用途では修正を取り込んだ最新ビルドを使ってください**（2026-06-01時点。安定版への取り込み状況は最新リリースで確認のうえ利用を）。
:::

## まとめ

- **「LFM2.5」は2系統**: 1月の密モデルと、5月のMoE（8B-A1B）は別物。混同しない。
- **A1B＝アクティブ1.5B / reasoning-only**: 8Bの知識量を1.5Bの速度で。毎回CoTが前置きされる。
- **221-253 tok/sは高位チップの数字**: 素のM5/16GBは実測 Q4 84・MLX-8bit 58 tok/s（公式の約1/3）。でも日常用途には十分実用。
- **16GBはQ4_K_Mが最適**: 8bitより速く軽い。
- **日本語は素直に良い／重コーディングは非推奨**: 用途を見極めれば強力なオンデバイス選択肢。

「速い速いと聞いたが、自分のMacで本当はどうなのか」——その答えを実測で出したのが本記事です。数字は盛らず、マシンで決まる前提で選びましょう。
