## 作ったもの

Instagram / X (Twitter) / TikTok / Pinterest / Tumblr / Bluesky のアカウントを登録して、動画・画像を**まるごとローカルに一括ダウンロード**、その後は**差分だけ追記**していけるローカルWebアプリを作りました。

**🔗 GitHub:** https://github.com/hrtaym1114-github/sns-media-archive
**🌐 ライブデモ（LP）:** https://hrtaym1114-github.github.io/sns-media-archive/

## なぜ作ったか

お気に入りのSNSアカウントの投稿を、ふと「**消える前にちゃんと手元に残しておきたい**」と思うことが増えました。

- 公式の保存機能（ブックマーク等）はアカウント側に依存しているので、削除・凍結されると見られなくなる
- 個別の "downloader" サイトは1投稿ずつしか落とせず、広告まみれで使い勝手が悪い
- CLIツール（`yt-dlp` / `gallery-dl`）はパワフルだけど、毎回コマンドを打つのは面倒

「**プロフィールURL貼って、ボタン1つで全部取得、次回からは差分だけ**」という自分専用UIが欲しかった、というのが起点です。

## 仕組み

### バックエンド：gallery-dl のオーケストレーション

ダウンロード自体は [`gallery-dl`](https://github.com/mikf/gallery-dl) に任せています。300以上のサイトに対応していて、特に SNS のプロフィール → 全メディア取得が非常に強い。

アプリ側でやっているのは:

- アカウントの登録／管理（`accounts.json`）
- 各アカウントに専用のメディアフォルダと **gallery-dl のアーカイブDB（SQLite）** を持たせる → 差分取得が自動で効く
- ジョブの起動／進捗追跡／停止（`subprocess` + `threading`）
- サムネイル生成（動画は `ffmpeg` で1フレーム抽出してキャッシュ）

バックエンドは **Python 標準ライブラリの `ThreadingHTTPServer` だけ**。Flask すら入れていない軽量構成です。

```python
PLATFORMS = {
    "instagram": {"label": "Instagram", "domains": ("instagram.com",),
                  "url": "https://www.instagram.com/{u}/"},
    "twitter":   {"label": "X (Twitter)",
                  "domains": ("twitter.com", "x.com"),
                  "url": "https://x.com/{u}"},
    "tiktok":    {"label": "TikTok", "domains": ("tiktok.com",),
                  "url": "https://www.tiktok.com/@{u}"},
    # ...
}
```

プロフィールURLを貼ると、ドメインを見てプラットフォームを自動判別 → gallery-dl にそのURLを渡すだけ。**新しいSNSを足すのもこのテーブルに1行追加する**程度の手間で済みます。

### フロントエンド：素の HTML/CSS/JS

フレームワーク無し。`fetch` で API を叩いて DOM を更新するだけ。
カードのアニメーション、ギャラリーのページング、ホバー拡大ポップ、矢印キーでのプレビュー切替、解除モーダル… 一つ一つ手書きですが、それでも 300 行ほどに収まりました。

フォントは **Fraunces ＋ IBM Plex** の組み合わせ、アクセントは琥珀色1色。よくある "AIっぽいダークテーマ" を避けたかった、というのが地味なこだわり。

### 認証：Chrome の cookie を使う

各SNSはログイン必須化が進み、匿名アクセスはほぼ不能。`gallery-dl --cookies-from-browser chrome` で**起動中の Chrome のログイン済みCookieを直接読める**ので、これに完全に任せています。ユーザーは事前に Chrome で各SNSにログインしておくだけ。

## 詰まったところ

### VP9 in mp4 問題

最初は `yt-dlp` の `-f bv*+ba/b` で取っていたら、**音声しか再生されない動画**が大量に生成されました。原因は Instagram の DASH ストリームが **VP9 を mp4 コンテナに格納した形式**で、QuickTime が再生できなかったこと。

`-f best`（プログレッシブ形式 = H.264 + AAC）に切り替えて解決。「**最高画質**」より「**確実に再生できる**」を優先しました。

### 数百件サムネ描画でブラウザがコケる

ギャラリーで全件（400件超）を一気に `<img>` 描画したら、ブラウザの描画が**横縞ノイズ状に崩れる**現象が出ました。**60件ずつページング** で解決。

「ローカルツールだから多少雑でも動くだろう」は意外と通用しません。

### `~/.Trash` への移動が不安定

「データ削除」を安全に行うため macOS の `~/.Trash` に移動する設計にしたかったのですが、サンドボックス／実行環境によって解決先がブレることがありました。

→ **アプリ内 `trash/` フォルダへ移動**する方式に変更。完全に消したいときは手動で `trash/` を空にする。シンプルで確実です。
