# はじめに

Claude Code や Codex を使い込むと、`CLAUDE.md` や `AGENTS.md` の周りにファイルが増えていきます。`.claude/rules/`、`.claude/agents/`、`.claude/skills/`、`.claude/commands/`、そして Codex 用の `.agents/skills/`。最初は1枚のメモだったものが、いつの間にか「エージェントが毎回読む設定の束」になります。

そして、その束は静かに壊れます。コマンドの名前を変えたのに、rules の中の古い名前はそのまま。使わなくなったエージェントの定義ファイルが残り続ける。「執筆は○○モデルで」と書いたモデル名が、もう既定値ではない。

人間なら「古いな」と読み飛ばせる記述も、エージェントは指示として読みます。存在しないファイルを探しに行き、廃止したコマンドを呼び、固定されたモデル名を前提に手順を組み立てます。

## 筆者のリポジトリで出た数字

筆者が Claude Code と Codex の両方から使っている個人リポジトリに、LLM を使わない静的チェック（[agent-docs-lint](https://github.com/hrtaym1114-github/agent-docs-lint) v0.1.0、既定設定）を当てた結果です。

| 時点 | 警告の数 |
| --- | --- |
| 2026-10-03 の手作業監査の直前 | 1,087 |
| 同じ日の監査コミット6本の直後 | 1,061 |
| 2026-10-12 09:00 時点 | **1,051** |

監査は Claude Code のセッションで行い、6本のコミットで直しました。それでも警告の差し引きは26件減っただけです。中身を見ると30件が消え、4件が新しく出ていました。新しい4件はどれも、監査で「直した」行から出たものです。

1,051件のうち、本当に直すべき腐りはどれか。どれがツールの誤検知で、どれが書き方の問題か。この本はその仕分けの記録です。

## この本で渡すもの

この本は「指示ファイルの書き方」の本ではありません。**書いたあとに腐らせない運用**の本です。

- 無料章（00〜03）: 指示ファイルが腐る仕組み、既存の検知手段（手作業監査・リンクチェッカー・LLMレビュー・静的lint）の比較、公式ドキュメントが何を約束していて何を約束していないか
- 有料章（04〜07）:
  - 04: 2026-10-03 の監査で実際に直した差分と、その一つひとつを静的lint・LLM監査が拾えたかの答え合わせ
  - 05: 1,051件の警告の内訳と、どれを除外し、どれを直し、どれを人が見るかの仕分け基準
  - 06: rules層・Claude Code の hooks・CI に入れる手順。スクリプト全文と、実際に動かしたときの出力つき
  - 07: そのまま貼れるチェックリスト

## 前提と、書かないこと

- 題材は筆者（hrtaym1114）の個人の Obsidian Vault 兼エージェント作業場です。チーム開発の大規模リポジトリではありません。
- 数字は、実際のコミットと、そのコミットを書き出したコピーに静的チェックを当てた結果だけを使います。実行は 2026-10-20 にやり直したもので、手順は章05に書きます。「何%改善した」のような効果測定はしていないので書きません。
- 内部のパスやファイル名、個人的な情報は、一般化して書き換えています。
- agent-docs-lint は筆者の自作で、実装の一例です。同じ考え方は数十行のスクリプトでも再現できます。本書の手順はツールに依存しません。
