# 既存の検知手段を比べる

腐りを見つける手段は、大きく4つあります。どれか1つで十分ということはなく、拾えるものが違います。次の表は筆者の整理による一般的な傾向で、測った数字は次の節に分けて書きます。

| 手段 | 拾えるもの | 拾えないもの | コスト | 再現性 |
| --- | --- | --- | --- | --- |
| 手作業監査 | 意図とのずれ、方針の古さ、全部 | 量が増えると見落とし | 高い（人の時間） | 低い |
| Markdownリンクチェッカー | `[text](path)` 形式のリンク切れ | バッククォート内のパス、スラッシュコマンド、モデル名、未参照ファイル | 低い | 高い |
| LLMレビュー | 文意の矛盾、古そうな記述、実在しない参照（読みに行けば） | 毎回同じ範囲・同じ結果になる保証 | 中〜高（トークンと時間） | 低〜中 |
| 静的lint（指示ファイル特化） | パス・コマンドの実在、固定トークン、未参照定義、アンカー | 意図とのずれ、方針の妥当性、外部ツールの仕様変更 | 低い | 高い |

## 筆者の環境で測ったコスト

同じリポジトリの、2026-10-03 の監査直前の状態を書き出したコピーで、2026-10-20 に測りました。

| 手段 | 対象 | 所要時間 | 費用 |
| --- | --- | --- | --- |
| 静的lint（agent-docs-lint v0.1.0） | リポジトリ全体の指示ファイル群（警告1,087件） | 約1.3秒（3回とも1.30〜1.31秒） | 0（LLM・ネットワークなし） |
| LLMレビュー（Claude Code の `/doctor prompt-audit`） | `CLAUDE.md` 1ファイルだけ | 約139秒、18ターン | 実行ログの list 価格換算で約1.53ドル |

LLMレビューは1ファイルでこのコストです。編集のたびに全体へ回す用途には向きません。逆に、静的lint が出した警告のうち、どれが本物かを考える力はありません。有料章04で、2つの手段がそれぞれ何を拾い、何を落としたかを、実際の監査の差分と突き合わせます。

## 手作業監査

いちばん確実で、いちばん続きません。筆者も監査は「気になったときにまとめて一度」しかやっていません（有料章04で、その一度の記録を全部出します）。

## Markdownリンクチェッカー

markdown-link-check や lychee のような汎用ツールです。CI に入れやすく、誤検知も少ない。ただし指示ファイルの参照は、多くが **リンク記法ではありません**。

```markdown
詳細は `.claude/docs/notion-integration.md` に従う
`/blog-write` 実行時にスラッグを付与
```

バッククォートで囲んだパスや、スラッシュコマンドは、汎用リンクチェッカーの対象外です。筆者のリポジトリ（2026-10-12 時点）では、存在しない参照の警告1,046件のうち、Markdown のリンク記法だったのは38件だけでした。しかもその38件は、どれも `[タイトル](URL)` のような書式見本で、本物のリンク切れではありませんでした。

## LLMレビュー

「この CLAUDE.md で古そうなところを指摘して」とエージェントに頼む方法です。Claude Code には、これを公式の機能にした `/doctor prompt-audit` があります（v2.1.283 以降。章03）。

文意レベルの矛盾には強く、ファイルを読みに行けば実在も確かめます。一方で、どこまで読むかはその回の判断で、結果がぶれます。CI のゲートには向きません。

## 静的lint（指示ファイル特化）

指示ファイルの文法（バッククォートのパス、スラッシュコマンド、エージェント・スキルの命名）を前提に、機械的に実在を確かめる方法です。LLM もネットワークも使わないので、毎回同じ結果が出ます。

ただし、**機械的に拾える = 全部が本物の腐り、ではありません**。有料章05で、1,051件の警告のうち、どれが本物でどれがノイズだったかを仕分けます。結論を先に書くと、生の警告をそのまま CI のゲートにすると運用が回りません。

## 組み合わせ方の目安

- 毎回: 静的lint（ベースラインから増えた分だけを見る。章06）
- 構成を大きく変えたとき: 手作業監査
- 方針を書き換えたとき: LLMレビューで矛盾だけ見る
