## A-1. CLAUDE.md の存在しない参照

```diff

+ ドキュメント作成時は `.claude/docs/notion-integration.md` に従う
```

`prompts/notion-up.md` は以前に消したファイルでした。この指示を読んだエージェントは、毎回ないファイルを探していたことになります。

```diff
- キュー: [[調査キュー]] / [[制作キュー]]。
+ キュー: [[調査キュー]]。
```

制作キューのファイルも、運用を変えたときに廃止していました。Obsidian のウィキリンク記法なので、汎用のリンクチェッカーでは拾えない種類です。

## A-2. CLAUDE.md の固定件数

```diff

+ 実体は `.claude/commands/`（実装）と `.claude/skills/`（...）
```

「約60本」「20本」は、書いた時点では正しい数字でした。2026-10-12 時点では、`.claude/commands/` 直下が66項目、`.claude/skills/` のスキルが22本です（ほかに README が1つ）。数を合わせ直すのではなく、**数そのものを消しました**。数は `ls` すれば分かり、指示としての価値がないからです。

## A-3. rules 内の改名漏れ（コマンド名）

## 答え合わせ: lint と LLM監査は、この監査の何を拾えたか

2026-10-20 に、監査直前のコミットと監査直後のコミットをそれぞれ書き出し、次の2つを流しました。

- 静的lint: agent-docs-lint v0.1.0。既定設定と、モデル名のトークン一覧だけを足した設定の2通り。対象はリポジトリ全体
- LLM監査: Claude Code v2.1.299 の `/doctor prompt-audit CLAUDE.md`。対象は CLAUDE.md の1ファイルだけ（費用の都合）

監査前後の lint の差分（ベースライン差分スクリプトで比較。章06）はこうでした。

```text
baseline=1087 now=1061 new=4 fixed=30
```

監査で直した項目ごとの結果です。

| 監査で直したもの | 静的lint（既定） | 静的lint（トークン一覧つき） | LLM監査（CLAUDE.md のみ） |
| --- | --- | --- | --- |
| 存在しないファイル参照（`prompts/...`） | 拾えた | 拾えた | 拾えた |
| 廃止したファイルへのウィキリンク | 拾えない（記法が対象外） | 拾えない | 拾えた |
| 固定件数「約60本・20本」 | 拾えない | 拾えない | 拾えた（「20本」は実数22本と指摘。提案差分では「約60本」も消していた） |
| rules のコマンド改名漏れ（2か所） | 拾えた。さらに同じ旧名が**ほかに7か所**あると出た | 同左 | 対象外（rules は見ていない） |
| 外部ツールの無効オプション | 拾えない | 拾えない | 対象外 |
| 未参照エージェント6本 | 拾えた（6件） | 同左 | 拾えない（CLAUDE.md の「図解5エージェント」も指摘なし） |
| 雛形の置き場所違い | 間接的（雛形内の参照が13件の警告になっていた） | 同左 | 対象外 |
| 固定モデル名・プラン | 拾えない（0件） | 拾えた（11件） | 拾えない（値がスクリプトの既定値と一致していたため「問題なし」） |

いくつか補足します。

**既定のトークン一覧では、モデル名は1件も出ません。** v0.1.0 の既定一覧は `gpt-4` や `claude-3-opus` のような古い名前だけです。自分の環境で使っている名前（ここでは `Gemini 3.8 Flash`、`gemini-3.8-flash-high`、`unlimitedプラン`）を設定に足すと、監査前のリポジトリで11件出ました。監査で消したのは rules と CLAUDE.md の6件で、残り5件はスキル側に残っていました。

**LLM監査は「いま正しい固定値」を腐りと見なしません。** モデル名はスクリプトの既定値と一致していたので、問題なしと判定されました。固定値の問題は「いつか古くなる」ことなので、正誤では見つかりません。

**LLM監査は、手作業監査が見落とした矛盾を拾いました。** CLAUDE.md と AGENTS.md が互いに「詳細は向こう」と指し合っている箇所、CLAUDE.md の中で作業場所の指示と安全ルールがぶつかっている箇所、同じきっかけで出る案内メニューが別ファイルに二重定義されている箇所の3つです。どれも静的lint では原理的に拾えません。

**監査が新しく生んだ警告が4件ありました。**

```text
NEW .claude/rules/blog-slug-metadata.md: dead_ref: missing slash command target: /blog-write
NEW .claude/rules/factcheck-metadata.md: dead_ref: missing slash command target: /blog-write
NEW .claude/rules/natural-japanese-rhythm.md: dead_ref: missing referenced path: write-with-gemini.sh (x2)
```

上の2件は、改名漏れを「正しい名前」に直した先に、実体のファイルがなかったものです（章05で詳しく見ます）。下の2件は、コミットBで書いた「正本の場所」がファイル名だけだったため、機械からは見つからない参照になったものです。直し方としては正しくても、書き方が機械に読めない形でした。章06の原則2は、ここから来ています。

**旧名の残り7か所は、2026-10-20 時点でもそのままです。** Claude Code 用と Codex 用のスキル（ミラー）に3件ずつと、登録表に1件。rules だけを見て直したので、ほかの層に残りました。

## 費用と時間

| 手段 | 所要時間 | 費用 |
| --- | --- | --- |
| 静的lint（全体） | 約1.3秒 | 0 |
| LLM監査（CLAUDE.md 1ファイル） | 約139秒・18ターン | list 価格換算で約1.53ドル |

LLM監査のこの回は、git の履歴がないコピーで動かしたため、どちらの記述が新しいかの判断を全部「人が決める」に回していました。履歴のある実リポジトリで動かせば、判断できる範囲は広がるはずです（推測）。

## この章のまとめ

- 手作業監査は「直す」には向くが、「漏れなく探す」には向かない。rules の2か所を直して、同じ旧名の7か所を残した
- 静的lint は「漏れなく探す」には向くが、ウィキリンク・固定件数・外部ツールの仕様・ファイル間の矛盾は拾えない。固定モデル名は、自分の環境のトークン一覧を設定しない限り拾えない
- LLM監査は矛盾に強いが、1ファイルでも分単位の時間と費用がかかる。正しい値は腐りと見なさない
- どの手段でも、直したあとにもう一度 lint を流さないと「直した先の腐り」が残る
