# 静的チェックを当てたら1,047件

監査から9日後の 2026-10-12、同じリポジトリに LLM なしの静的チェック（agent-docs-lint v0.1.0、既定設定、`--warn-only --json`）を読み取り専用で当てました。

## 生の結果（2026-10-12実測）

| ルール | 件数 |
| --- | --- |
| dead_ref（存在しない参照） | 1,042 |
| unreferenced_agent（未参照の定義） | 5 |
| model_name（固定モデル名） | 0 |
| broken_anchor（アンカー切れ） | 0 |
| **合計** | **1,047** |

model_name が0件なのは、10/03 のコミットBで外した直後だからです（ただし既定のトークン一覧に載っている名前だけの話です）。

ファイル群別では、`.claude/skills` 445件、`.agents/skills` 390件、`.claude/agents` 162件、`.claude/rules` 43件、`CLAUDE.md` 5件、`AGENTS.md` 2件でした。

1,047件をそのまま CI のエラーにしたら、誰も見なくなります。ここからが本題の仕分けです。

## dead_ref 1,042件の内訳

まず種類で機械的に分けました。

| 種類 | 件数 | 典型例 |
| --- | --- | --- |
| スラッシュコマンドが見つからない | 437 | `/blog-write`、`/note`、`/wiki` |
| 参照パス（ディレクトリつき）が見つからない | 199 | `references/prompt-patterns.md`、`@TODO/` |
| ファイル名だけの参照が見つからない | 253 | `build.py`、`podcast.py` |
| テンプレート・プレースホルダ | 153 | `YYYYMMDD_[内容].md`、`05_Output/.../` |
| （うちMarkdownリンク記法） | 38 | — |

### ノイズ1: プレースホルダ（153件）

`YYYYMMDD_[内容].md` や `.../` を含むパスは、手順の説明であって参照ではありません。**全部ノイズ**です。lint 側で `{` `[` `<` `YYYY` `...` を含むトークンを除外すれば消せます。

### ノイズ2: 相対基準の違い（ファイル名だけの253件と、パスの一部）

スキルの `SKILL.md` に書かれた `build.py` は、スキルのディレクトリでも、リポジトリのルートでもなく、**スクリプト置き場からの相対**で書かれていました。人間とエージェントには文脈で分かりますが、機械には分かりません。

ここは「ノイズ」と切り捨てずに、**書き方を揃える**ほうを選びました。エージェントも同じ迷い方をするからです（章06）。

### ノイズ3: 出力先・作業用ディレクトリ

`@TODO/`、`@Doing/`、`@Completed/` などは、実行時に作られる、あるいは別の場所にある作業ディレクトリです。ignore リストで除外します。

### 判断が要るもの: スラッシュコマンド（437件）

437件はコマンド名63種類から出ていました。上位は `/blog-write` 26件、`/note` 26件、`/email-daily-check` 25件、`/wiki` 23件。

ここに、ツールと実運用の「名前の解決規則のずれ」がありました。

- `/note` や `/wiki` は、`commands/note/` のように **ディレクトリで名前空間を切ったコマンド** です。ファイル単位で探す lint からは「ない」と見えます。→ ツール側の誤検知
- `/blog-write` は、10/03 の監査で正しい名前として **直した先** です。ところが `commands/` にも `skills/` にも同名のファイルはなく、`blog` スキル内の手順として呼ばれています。→ 監査で「直した」つもりの参照が、実体のファイルを持っていない。本物かどうかは人間の確認待ち

二つ目は、手作業監査の限界をよく表しています。「新しい名前に揃えた」ことと「その名前で実体が見つかる」ことは別です。

### 二重管理: 200件は同じ指摘

`.claude/skills` と `.agents/skills` の指摘を、スキル内の相対パスとメッセージで突き合わせると、**200件が完全に同じ指摘** でした（`.agents` 側226件、`.claude` 側258件）。Codex 用のミラーをコピーで作っているため、腐りもそのままコピーされています。差の分（`.claude` 側だけの58件など）は、ミラーがすでにずれている証拠でもあります。

## unreferenced_agent 5件

エージェント1本、スキル4本が「ファイル名でどこからも参照されていない」と出ました。指示ファイル以外（システム用のフォルダ）まで名前で検索すると、5本中3本はスキル一覧の棚卸し表・評価記録・状態ファイル・スクリプト側に名前が出てきました。残り2本は、検索した範囲ではどこにも出てきませんでした。

つまり **未参照 = 不要、とは限りません**。呼び出し元や管理表が指示ファイルの外（スケジューラ、CI、シェル、棚卸し表）にある定義は、許可リストに入れます。どこにも名前が出てこないものだけが、アーカイブ候補です。この5本の最終判断は、この記録の時点ではまだしていません。

## 仕分けの結論

| 区分 | 扱い |
| --- | --- |
| プレースホルダ・出力先 | lint 設定で除外（恒久） |
| 名前空間つきコマンド | ツール側の誤検知として除外 |
| 相対基準がばらばらなパス | 書き方を揃えて直す |
| ミラーの重複 | ミラーを生成物にして片方だけ lint する |
| 実体のないコマンド名・未参照定義 | 人間が1件ずつ確認 |

この記録時点では、本物の腐りが何件かを最後まで数え切っていません。正直に書くと、**「1,047件」は腐りの数ではなく、仕分けが必要な数** です。この区別を持たずに静的チェックを入れると、ほぼ確実に `--warn-only` のまま放置されます。
