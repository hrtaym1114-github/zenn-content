# 静的チェックを当てたら1,051件

監査から9日後の 2026-10-12 時点のリポジトリに、LLM なしの静的チェック（agent-docs-lint v0.1.0、既定設定、`--warn-only --json`）を当てた結果を仕分けます。

## 先に失敗の記録: 最初の結果を保存していなかった

この本の下書きを書いた 2026-10-12、同じチェックを作業中のリポジトリに一度流し、「1,047件」という数字を下書きに書きました。出力の JSON も、どの状態のリポジトリに流したかも、記録に残していませんでした。

あとで数字の出どころを確かめようとしたところ、再現できませんでした。その日のコミットを書き出して流すと1,051件、2026-10-20 の作業ツリーでは1,049件です。差の4件は、未コミットの変更か、git に入っていないファイル（参照先として実在していたもの）の違いだと思われます（推測）。

そこで本書の数字は、**2026-10-12 09:00 時点のコミットを書き出したコピーに対して、2026-10-20 にやり直した結果（1,051件）** に揃えました。誰がいつ流しても同じ結果になるのは、コミットを指定したこの形だけです。

教訓は単純で、**警告の数を記録するなら、出力ファイルとコミットを一緒に残す**ことです。章06のベースラインは、この失敗の直し方でもあります。

再実行の手順はこうです（リポジトリは読むだけで、書き出し先は別ディレクトリ）。

```sh
git -C <リポジトリ> archive <コミット> | tar -x -C /tmp/snapshot
cd /tmp/snapshot && agent-docs-lint . --warn-only --json > run.json
```

model_name が0件なのは、腐りがないからではありません。v0.1.0 の既定のトークン一覧が `gpt-4` のような古い名前だけだからです。自分の環境のモデル名を設定に足すと、監査前のリポジトリで11件出ました（章04）。

ファイル群別では、`.claude/skills` が446件、`.agents/skills` が392件、`.claude/agents` が162件、`.claude/rules` が43件、`CLAUDE.md` が6件、`AGENTS.md` が2件でした。

1,051件をそのまま CI のエラーにしたら、誰も見なくなります。ここからが本題の仕分けです。

## dead_ref 1,046件の内訳

まず種類で機械的に分けました。分類のルールは次のとおりです。

- プレースホルダ: 参照先に `{` `[` `<` `*` `YYYY` `...` `XXX` のどれかを含むもの。または、リンク記法の参照先に `.` も `/` もないもの（`[タイトル](URL)` の `URL` など）
- スラッシュコマンド: `/xxx` 形式のもの
- 残りは、`/` を含むかどうかで「ディレクトリつきのパス」と「ファイル名だけ」に分ける

| 種類 | 件数 | 典型例 |
| --- | --- | --- |
| スラッシュコマンドが見つからない | 437 | `/blog-write`、`/note`、`/wiki` |
| プレースホルダ | 219 | `YYYYMMDD_[内容].md`、`Inbox-Sync/*.json`、`[タイトル](URL)` |
| ファイル名だけの参照が見つからない | 203 | `build.py`、`podcast.py`、`channel-registry.md` |
| ディレクトリつきのパスが見つからない | 187 | `references/prompt-patterns.md`、`@TODO/` |

### ノイズ1: プレースホルダ（219件）

`YYYYMMDD_[内容].md` や `*.json` を含むパスは、手順の説明であって参照ではありません。**全部ノイズ**です。lint 側で上の記号を含むトークンを除外すれば消せます。

Markdown のリンク記法で書かれた警告38件は、**38件すべてが** `[タイトル](URL)` や `[元記事](元記事URL)` のような書式見本でした。汎用のリンクチェッカーをこのリポジトリに入れても、本物の腐りは1件も見つからなかったことになります。

### ノイズ2: 相対基準の違い（ファイル名だけの203件の一部）

スキルの `SKILL.md` には、たとえばこう書かれていました。

```markdown
- 実装: `scripts/news-site/`（`build.py` / `podcast.py` / `publish.py`）
```

`build.py` は、直前に書いたディレクトリからの相対です。人間には文脈で分かりますが、機械には分かりません。203件を1件ずつは確かめていません。確かめた `build.py`・`podcast.py`・`publish.py` は、この形でした。

ここは「ノイズ」と切り捨てずに、**書き方を揃える**ほうを選びました。エージェントも同じ迷い方をするからです（章06の原則2）。

### ノイズ3: 出力先・作業用ディレクトリ

`@TODO/`、`@Doing/`、`@Completed/` などは、実行時に作られる、あるいは別の場所にある作業ディレクトリです。`@` で始まる参照は41件ありました。ignore リストで除外します。

### 判断が要るもの: スラッシュコマンド（437件）

437件は、コマンド名63種類から出ていました。上位は `/blog-write` 26件、`/note` 26件、`/email-daily-check` 25件、`/wiki` 23件です。

63種類を、リポジトリに何があるかで3つに分けました。

| 区分 | 種類 | 件数 | 例 | 扱い |
| --- | --- | --- | --- | --- |
| `commands/` に同名のディレクトリがある | 4 | 61 | `/note`、`/wiki` | ツール側の誤検知 |
| `skills/` に同名のスキルがある | 6 | 42 | `/blog`、`/url-digest` | ツール側の誤検知 |
| どこにも同名の実体がない | 53 | 334 | `/blog-write`、`/email-daily-check` | 人が確認 |

上の2つは、v0.1.0 の名前の解決規則と、実際の置き方がずれていることによる誤検知です。`/note` は `commands/note/` というディレクトリで名前空間を切ったコマンドです。`/blog` は `skills/blog/SKILL.md` というスキルです。v0.1.0 は「`note.md` や `blog.md` というファイルがあるか」で探すので、どちらも「ない」と出ます。合わせて103件は、ツールを直せば消えます。

3つ目の334件が、本当に人の判断が要る部分です。代表例が `/blog-write` です。これは 10/03 の監査で、改名漏れを **直した先** の名前でした。ところが `commands/` にも `skills/` にも同名のファイルはなく、`blog` スキルの中の手順の名前として書かれています。

> 監査で「直した」つもりの参照が、実体のファイルを持っていなかった。

手作業監査の限界をよく表しています。「新しい名前に揃えた」ことと「その名前で実体が見つかる」ことは別です。334件が全部本物の腐りかどうかは、この記録の時点ではまだ確かめ切れていません。

### 二重管理: 357件は同じ指摘

`.claude/skills` と `.agents/skills` の警告を、「スキル内の相対パス・ルール・メッセージ」が同じかどうか（行番号は見ない）で突き合わせました。**357件が完全に同じ指摘** でした。`.claude` 側にしかないのが89件、`.agents` 側にしかないのが35件です。

Codex 用のミラーをコピーで作っているので、腐りもそのままコピーされています。片側にしかない124件は、ミラーがすでにずれている証拠でもあります。

## unreferenced_agent 5件

エージェント1本とスキル4本が、「ファイル名でどこからも参照されていない」と出ました。指示ファイルの外まで名前で検索すると、こうなりました。

- 3本は、システム用のフォルダ（スキル棚卸し表、評価記録、状態ファイル、廃止済みスクリプトの控え）に名前が出てきた
- 2本は、システム用のフォルダにはなく、個人のメモにだけ名前が出てきた

つまり **未参照 = 不要、とは限りません**。呼び出し元や管理表が指示ファイルの外（スケジューラ、CI、シェル、棚卸し表）にある定義は、許可リストに入れます。どこからも呼ばれていないと確かめられたものだけが、アーカイブ候補です。この5本の最終判断は、この記録の時点ではまだしていません。

## 仕分けの結論

| 区分 | 件数（10/12時点） | 扱い |
| --- | --- | --- |
| プレースホルダ | 219 | lint 設定で除外（恒久） |
| 出力先・作業用ディレクトリ | `@` で始まるもの41件ほか | ignore リストで除外（恒久） |
| 名前空間・スキル名のコマンド | 103 | ツール側の誤検知として除外、またはツールを直す |
| 相対基準がばらばらなパス | ファイル名だけの203件の一部（全件は未確認） | 書き方を揃えて直す |
| ミラーの重複 | 357 | ミラーを生成物にして、片方だけ lint する |
| 実体のないコマンド名 | 334 | 人が1件ずつ確認 |
| 未参照定義 | 5 | 呼び出し元を確かめ、許可リストかアーカイブ |

区分は重なっています（ミラーの357件の中にプレースホルダもコマンドも含まれる）。足しても1,051にはなりません。

この記録の時点では、本物の腐りが何件かを最後まで数え切っていません。正直に書くと、**「1,051件」は腐りの数ではなく、仕分けが必要な数** です。この区別を持たずに静的チェックを入れると、ほぼ確実に `--warn-only` のまま放置されます。
