# 直し方と再発防止

章04と05から、直し方を手順にします。

## 原則1: 値ではなく「正本の場所」を書く

モデル名・件数・残量・プラン名は、指示ファイルに書かない。代わりに、

- 正本のファイル（例: スクリプトの既定値 `AGY_MODEL`）
- 確認コマンド（例: `ls .claude/commands | wc -l`、状態確認ツール）

を書きます。コミットBがこの形です。直す頻度がゼロになります。

## 原則2: 参照は1つの基準で書く

- リポジトリルートからのパスに統一する。スキル内だけで閉じる参照は `./` から始めて明示する
- プレースホルダは `<日付>_<内容>.md` のように、実在パスと見分けがつく記法に揃える
- スラッシュコマンドは、名前空間を使うなら `/note:xxx` のように実際の呼び方で書く

## 原則3: ミラーは手で持たない

`.claude/skills` と `.agents/skills` のような二重管理は、片方を正本にして、もう片方はスクリプトで生成します。lint は正本だけに当てます。

## 原則4: 改名は grep とセットにする

コマンドやファイルを改名するときは、指示ファイル群全体を grep してから閉じる。これを rules に書いておきます。

```markdown
<!-- .claude/rules/ 配下の例 -->
## 改名・削除時
コマンド・スキル・エージェント・参照ファイルを改名または削除したら、
CLAUDE.md / AGENTS.md / .claude/ / .agents/ を旧名で検索し、残った参照を同じ変更で直す。
```

ただし公式ドキュメントのとおり、CLAUDE.md や rules は「文脈」であって強制ではありません。守らせたい場合は次の hooks へ。

## hooks: 書いた直後に止める

Claude Code の PostToolUse フックで、指示ファイルが編集されたときだけ静的チェックを回します。

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          { "type": "command", "command": "scripts/lint-agent-docs-if-changed.sh" }
        ]
      }
    ]
  }
}
```

スクリプト側は、編集されたパスが `CLAUDE.md`・`AGENTS.md`・`.claude/`・`.agents/` 配下のときだけ lint を実行し、エラーを標準エラーに返します。hooks の入出力仕様はバージョンで変わるので、公式ドキュメントで確認してから組んでください。

## CI: 新しく増えた分だけ落とす

既存の警告が数百件あるリポジトリで、いきなり「警告ゼロ」をゲートにするのは無理です。

1. 現状の警告を JSON で保存し、ベースラインとしてコミットする
2. CI ではベースラインとの差分だけを見て、**新規の警告が出たら落とす**
3. 直した分はベースラインから消す（数が減る方向にしか動かない）

```sh
agent-docs-lint . --json --warn-only > /tmp/now.json
python3 scripts/diff_baseline.py lint-baseline.json /tmp/now.json  # 新規があれば exit 1
```

`diff_baseline.py` は「パス＋ルール＋メッセージ」をキーにした集合差を取るだけの数十行で書けます（行番号はキーに含めない。前後の行が動くたびに新規扱いになるため）。

## 手作業監査の頻度

静的チェックで拾えない種類（外部ツールの仕様変更、方針の古さ）のために、手作業監査は残します。目安は「ワークフローを置き換えたとき」と「外部ツールのメジャー更新のとき」。定期ではなく、出来事に紐づけたほうが続きます。
