# チェックリスト

コピーして、自分のリポジトリの rules やイシューテンプレートに貼ってください。各項目の後ろの括弧は、根拠になった章です。

## 書くとき

- [ ] モデル名・プラン名・件数・残量を書いていない。書くなら正本の場所と確認コマンド（章04 B）
- [ ] 「正本の場所」はファイル名だけでなく、ルートからのパスで書いた（章04・章06 原則2）
- [ ] パスはリポジトリルート基準、またはスキル内なら `./` から始めている（章05 ノイズ2）
- [ ] プレースホルダは実在パスと見分けがつく記法（`<...>`）で書いた（章05 ノイズ1）
- [ ] スラッシュコマンドは実際の呼び方で書いた。名前空間つきならそのまま（章05）
- [ ] 「絶対に守らせたいこと」は指示ファイルではなく hooks にある（章03）

## 改名・削除するとき

- [ ] 旧名で CLAUDE.md / AGENTS.md / `.claude/` / `.agents/` を検索した。rules だけで終えていない（章04 A-3）
- [ ] 置き換え先の名前に **実体のファイル** がある。新しい名前に揃えただけで終わっていない（章05）
- [ ] 直したあとに lint をもう一度流し、新規の警告が出ていない（章04 答え合わせ）
- [ ] 使わなくなったエージェント・スキルはアーカイブへ移した（章04 A-5）
- [ ] 雛形はエージェント定義の置き場所に混ぜていない（章04 A-5）

## 二重管理

- [ ] Claude Code 用と Codex 用のどちらが正本か決めている（章05 二重管理）
- [ ] もう片方は生成物で、手で編集していない
- [ ] CLAUDE.md と AGENTS.md に同じ方針を二重に書いていない。互いに「詳細は向こう」と指し合っていない（章04 答え合わせ）

## 静的チェック

- [ ] プレースホルダ・出力先ディレクトリを除外設定に入れた（章05）
- [ ] 自分の環境で使っているモデル名・プラン名をトークン一覧に足した。既定一覧のままにしていない（章04・章05）
- [ ] 指示ファイルの外から呼ばれる定義（スケジューラ・CI・棚卸し表）を許可リストに入れた（章05 unreferenced_agent）
- [ ] 現状の警告をベースラインとして保存し、新規だけを hooks と CI で見ている（章06）
- [ ] 警告の数を記録するときは、出力ファイルとコミットも一緒に残した（章05 失敗の記録）
- [ ] 警告数を「腐りの数」と読んでいない（章05）

## 監査するとき

- [ ] 外部ツールのオプション値・仕様を実機で確かめた。静的チェックでは拾えない（章04 A-4）
- [ ] ファイル間の矛盾は LLM 監査か人の目で見た。静的チェックでは拾えない（章04 答え合わせ）
- [ ] 差分は人間がレビューしてからコミットした
- [ ] 監査の内訳（何が何件）を、出力ファイルと一緒に記録に残した
