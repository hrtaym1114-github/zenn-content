# 第6章: Claudeに効くプロンプトの5原則

あなたはClaudeに「企画書を書いて」と頼んだことはありますか。返ってきた文章を見て、「なんか違うな」と思った経験はないでしょうか。実はそれ、Claudeの能力不足ではなく、「頼み方」に原因があるかもしれません。

この章では、Claudeから期待通りの回答を引き出すための5つの基本原則を紹介します。難しいテクニックは一切ありません。すべて「人に仕事を頼むとき、どうすればうまくいくか」という日常の延長線上にあります。

## 6.1 なぜ「頼み方」で結果がこんなに変わるのか

**Claudeの回答品質は、あなたの指示の品質で決まります。**

これは、職場で同僚に仕事を頼む場面を想像するとわかりやすいでしょう。

たとえば、あなたがチームのメンバーに「資料を作って」とだけ伝えたとします。メンバーは困惑するはずです。「何の資料？」「誰に見せるの？」「いつまでに必要？」「どれくらいの分量？」。質問が次々に浮かぶでしょう。結果として、あなたが思い描いていたものとはまったく違う資料が出来上がります。

Claudeもまったく同じです。曖昧に頼めば、曖昧な結果が返ってきます。

Anthropic社（Claudeの開発元）が公式に推奨している「金のルール」があります。

:::message
**金のルール**: あなたが書いた指示を、その仕事の背景を知らない同僚に見せてください。もし同僚が「何をすればいいのかわからない」と困惑するなら、Claudeも同じように困惑します。
:::

このルールを覚えておくだけで、プロンプト（Claudeへの指示文）の質は格段に上がります。

では、具体的にどう頼めばいいのか。5つの原則を順番に見ていきましょう。


## 6.2 原則1 --- 具体的に伝える

**曖昧な依頼は曖昧な成果物しか生みません。背景・目的・条件を明示するだけで、出力の精度は劇的に変わります。**

### 何を具体的にすればいいのか

仕事を人に頼むとき、優秀な依頼者は次の4つを伝えます。

1. **背景**: なぜこの仕事が必要なのか
2. **目的**: この成果物は何に使うのか
3. **読み手**: 誰がこれを読むのか（見るのか）
4. **成功の条件**: どうなっていれば「うまくいった」と言えるのか

Claudeへの指示でも、この4つを意識するだけで結果が大きく変わります。

### Before/After で見る改善例

**Before（曖昧な指示）**:

```
企画書を書いてください。
```

この指示では、Claudeは何のテーマの企画書かもわかりませんし、どんなトーンで書くべきかも判断できません。結果は「それっぽいが的外れな企画書」になりがちです。

**After（具体的な指示）**:

```
以下の条件で企画書のドラフトを書いてください。

テーマ: 30代共働き世帯向けの食材宅配サブスクリプションサービス
目的: 来週の部長会議で新規事業として提案するため
読み手: 事業開発部の部長（50代、数字を重視する方）
条件:
- A4で2ページ以内
- 市場規模、ターゲット、差別化ポイント、収益モデルを含める
- 結論（やるべき理由）を冒頭に記載
```

この指示なら、Claudeは「誰に」「何のために」「どんな形式で」書けばよいかが明確にわかります。出来上がる企画書の精度は、曖昧な指示とは比較にならないほど高くなります。

### 日常のメールでも同じ

仕事のメールを頼む場合も同様です。

**Before**:

```
クライアントにメールを書いて。
```

**After**:

```
以下の状況でクライアントへのメールを書いてください。

状況: 先方から依頼された見積もりの提出が2日遅れている
相手: 株式会社ABCの田中部長（3年来の取引先、関係は良好）
目的: 遅延のお詫びと、明後日までに提出する旨を伝える
トーン: 丁寧だが堅すぎない。信頼関係を損なわない表現で
```

「4つの要素（背景・目的・読み手・成功条件）を意識する」。たったこれだけの習慣が、Claudeの回答品質を一段上に引き上げます。


## 6.3 原則2 --- お手本を見せる

**「こんな感じで」と1つ例を添えるだけで、Claudeの出力品質は驚くほど安定します。**

あなたが新しいアルバイトに仕事を教えるとき、「こういう風にやってね」と実例を見せるのが最も効率的ではないでしょうか。言葉で長々と説明するよりも、「これがお手本だから、同じ形式でお願い」と言うほうが伝わります。

Claudeも同じです。過去の成果物や理想的なアウトプットを1つから3つ見せるだけで、形式・トーン・情報量のすべてが安定します。

### 実践: 議事録のフォーマットを統一する

たとえば、チームの議事録を毎回Claudeに書いてもらいたいとしましょう。

**お手本なしの場合**:

```
今日の会議の内容をまとめてください。
参加者は営業部の佐藤、鈴木、マーケ部の高橋です。
新製品の販売戦略について話しました。
```

この指示だけでは、Claudeは自分なりのフォーマットで議事録を作ります。毎回形式が変わる可能性もあります。

**お手本を添えた場合**:

```
以下の会議メモを、お手本と同じ形式の議事録にまとめてください。

【お手本】
---
件名: 第3回マーケティング戦略会議
日時: 2026年1月15日 14:00-15:00
参加者: 田中（部長）、山田、木村
議題: Q1キャンペーン企画の最終決定

■ 決定事項
1. SNS広告のターゲット層を25-34歳に絞る
2. キャンペーン期間は3月1日-31日

■ アクションアイテム
- 山田: 広告クリエイティブ案を2/20までに3パターン作成
- 木村: 予算配分の詳細を2/18までに提出

■ 次回予定
2026年2月5日 14:00- 広告案レビュー
---

【今日の会議メモ】
参加者は営業部の佐藤、鈴木、マーケ部の高橋。
新製品Xの販売戦略について。
佐藤が1月の営業成績を報告。目標比85%。
鈴木から価格改定の提案あり。高橋はSNS施策を検討中。
次のアクションとして佐藤が競合分析を来週まで、高橋がSNS投稿案を金曜まで。
次回は2月18日。
```

お手本が1つあるだけで、Claudeは「件名」「日時」「参加者」「決定事項」「アクションアイテム」「次回予定」という構造を正確に再現します。

### お手本を使うときのコツ

- **1つでも十分、3つあれば理想的**: お手本の数は多いほど安定しますが、1つでも効果は絶大です
- **「悪い例」と「良い例」のセットも効果的**: 「こういうのは避けてほしい」という例も添えると、Claudeの判断基準が明確になります
- **完璧でなくてOK**: お手本は過去の自分の成果物で構いません。Claudeはそのフォーマットと方向性を読み取ります


## 6.4 原則3 --- 役割を与える

**「あなたは○○の専門家です」と一言添えるだけで、Claudeの回答の深さと的確さが変わります。**

会社で誰かに相談するとき、「経理部の視点で見ると」「お客様目線で考えると」と立場を指定すると、その視点に沿った回答が返ってきます。Claudeでも、具体的な役割を伝えることで、その分野の専門知識やトーンを引き出すことができます。

### 具体的であるほど良い

ポイントは、役割をできるだけ具体的に設定することです。

| 曖昧な役割 | 具体的な役割 |
|-----------|-------------|
| マーケティングの専門家 | SaaS企業で10年の経験がある、BtoBマーケティングのシニアマネージャー |
| 法律に詳しい人 | 中小企業の労務問題を専門とする社会保険労務士 |
| 文章が上手い人 | 日経ビジネス系のビジネスメディアで5年以上執筆経験のあるライター |

左と右の指示では、Claudeから返ってくる回答の具体性と専門性がまったく異なります。

### 実践例: 同じ質問を違う役割で聞いてみる

試しに、同じ質問を2つの異なる役割で投げてみましょう。

**指示A**:

```
あなたは製造業の中小企業で20年の経験がある経営コンサルタントです。

質問: 従業員50名の工場で、残業時間を月平均20時間削減するには、
何から手を付けるべきですか？
```

**指示B**:

```
あなたは労働基準監督署で10年の勤務経験がある元労働基準監督官です。

質問: 従業員50名の工場で、残業時間を月平均20時間削減するには、
何から手を付けるべきですか？
```

同じ質問でも、経営コンサルタントは「生産性改善」「工程分析」「設備投資」の観点から回答し、元監督官は「36協定」「勤怠管理」「法的リスク」の観点から回答します。役割を変えるだけで、異なる角度のアドバイスが得られるのです。

### Projectsのカスタムインストラクションで役割を固定する

第3章で紹介したProjectsのカスタムインストラクションに役割を書いておけば、毎回指定する手間が省けます。たとえば「営業アシスタント」プロジェクトに「あなたは当社の営業チームに10年在籍しているベテラン営業です。商品知識に精通し、顧客への提案書作成を得意としています」と設定しておけば、そのプロジェクト内のすべての会話で営業の視点からの回答が得られます。


## 6.5 原則4 --- 構造を与える

**情報を整理して渡すと、Claudeも整理された回答を返してくれます。**

仕事を依頼するとき、箇条書きのメモを渡すのと、口頭で長々と説明するのとでは、相手の理解度が違います。Claudeへの指示も同じで、情報を構造的に整理して渡すほど、正確に意図を汲み取ってくれます。

### 箇条書きと見出しを使う

最も簡単な構造化は、箇条書きと見出しの活用です。

**構造化なし**:

```
来週の営業会議で使うプレゼン資料の構成案を考えてほしいんですけど、
内容は先月の売上実績の振り返りと今月の目標と重点施策で、
聞き手は営業部のメンバー15名と部長で、時間は30分です。
```

**構造化あり**:

```
営業会議のプレゼン資料の構成案を作成してください。

■ 目的
先月の振り返りと今月の方針を共有する

■ 内容に含めるもの
- 先月の売上実績（目標比・前年比）
- 今月の売上目標
- 重点施策3つ

■ 条件
- 聞き手: 営業部メンバー15名 + 部長
- 発表時間: 30分
- スライド枚数: 10枚以内
```

同じ内容でも、構造化するだけでClaudeは各要素を正確に把握できます。

### Claudeに特に効く「カッコで囲む」テクニック

Claudeには、情報の種類ごとに「カッコ」で囲んで渡すと、特に精度よく処理してくれる特徴があります。これはHTMLのタグに似た書き方で、`<タグ名>` と `</タグ名>` で情報を囲みます。

たとえば、こんな風に使います。

```
以下の背景情報と条件をもとに、提案書を作成してください。

<背景>
当社は従業員100名のITサービス会社です。
現在、営業チームの日報管理にExcelを使っていますが、
入力漏れが多く、週次レポートの作成に毎回3時間かかっています。
</背景>

<条件>
- 読み手: 経営企画部の部長（ITに詳しくない）
- 予算感: 年間200万円以内
- 導入時期: 今年度中
</条件>

<出力形式>
1. 現状の課題（3行以内）
2. 提案するソリューション
3. 期待される効果（定量的に）
4. 概算費用
5. 導入スケジュール
</出力形式>
```

このカッコで囲むテクニックには、3つのメリットがあります。

1. **情報の区切りが明確になる**: 「ここからここまでが背景情報」「ここからが条件」とClaudeが正確に理解できる
2. **出力形式を指定しやすい**: `<出力形式>` の中に書いた構造がそのまま反映されやすい
3. **長い指示でも混乱しない**: 複数の情報を渡す場合でも、各ブロックが独立しているため混線しにくい

タグの名前は自由につけて構いません。`<背景>` でも `<前提条件>` でも `<context>` でも、意味が通じる名前であれば何でもOKです。

:::message
**補足**: Claudeは構造化されたプロンプトへの反応が特に良好で、Anthropic公式もXMLタグの使用を強く推奨しています。Claudeの大きな強みの1つなので、ぜひ活用してください。
:::


## 6.6 原則5 --- 段階的に進める

**大きな仕事は一度に頼まず、ステップに分けて順番に依頼しましょう。**

あなたは部下に「新規事業の企画書を最初から最後まで一気に作って」と頼むでしょうか。普通は「まず市場を調べて」「次に構成案を出して」「それからドラフトを書いて」と段階を踏むはずです。

Claudeへの依頼も同じです。複雑なタスクを一発で完了させようとすると、どこかで品質が落ちます。ステップに分けることで、各段階の品質を確認しながら進められます。

### 実践: 企画書を4ステップで作る

「新規サービスの企画書」を例に、段階的に進める方法を見てみましょう。

**ステップ1: 調査**

```
食材宅配サービスの市場について教えてください。
- 国内の市場規模と成長率
- 主要なプレイヤーと特徴
- ユーザーの主な不満点やニーズ
箇条書きで簡潔にまとめてください。
```

Claudeの回答を確認し、方向性を確認したうえで次に進みます。

**ステップ2: 構成案**

```
ありがとうございます。この調査結果を踏まえて、
30代共働き世帯向けの食材宅配サービスの企画書の構成案を
3パターン出してください。
各パターンの特徴と差別化ポイントを1行で添えてください。
```

3つの案からベストなものを選びます。

**ステップ3: 本文作成**

```
パターン2が良いですね。この構成で企画書の本文を書いてください。
各セクションは200〜300字で、データや数字を根拠として含めてください。
読み手は事業開発部の部長です。
```

**ステップ4: 推敲**

```
この企画書を以下の観点でブラッシュアップしてください。
- 数字の説得力を高める
- 「なぜ今やるべきか」の緊急性を強調する
- 結論（冒頭のサマリー）をより力強い表現にする
```

4つのステップに分けることで、各段階の方向性を確認しながら進められます。一発で頼むよりも結果的に速く、しかも高品質な企画書が仕上がります。

### 「一往復で終わらせない」という発想

Claudeとのやり取りは、チャット形式の対話です。一度の指示で完璧な結果を求めるのではなく、「対話を重ねて完成度を上げていく」という発想が大切です。

以下のような一言を加えるだけでも、出力の質が上がります。

- 「まず構成案だけ出してください。本文はまだ書かないでください」
- 「続けて、第2章を書いてください」
- 「いい感じです。ただ、冒頭の部分をもう少し具体的にしてもらえますか」

この「段階的に進める」習慣は、後の章で紹介するドキュメント作成（第7章）やアイデア発想（第10章）でも繰り返し活用しますので、ぜひここで感覚をつかんでおいてください。


## 6.7 Claudeに特に効く2つのテクニック

5原則をおさえたうえで、Claudeならではの強みを活かすテクニックを2つ紹介します。

### テクニック1: 大量の参考資料を渡す

Claudeは一度に約500ページ分のテキストを処理できます。これは他のAIツールと比較しても突出した能力です。

この強みを活かすには、関連資料を惜しまず渡してしまうのが効果的です。

```
以下の3つの資料を踏まえて、次回の営業会議で使える
競合分析レポートを作成してください。

<資料1>
（競合A社の決算説明資料をコピー&ペースト）
</資料1>

<資料2>
（競合B社の新サービスに関するプレスリリース）
</資料2>

<資料3>
（業界レポートの該当セクション）
</資料3>

分析の観点:
- 各社の強み・弱み
- 当社が勝てるポイント
- 注意すべき脅威
```

「こんなに長い文章を渡して大丈夫？」と心配される方もいますが、Claudeはむしろ情報が豊富なほうが正確に回答できます。遠慮なく資料を渡しましょう。

### テクニック2: Projectsとの組み合わせ

第3章で紹介したProjectsのカスタムインストラクションは、「毎回書くのが面倒な指示」を事前に設定しておく機能です。

5原則のうち、以下の要素はProjectsに一度設定すれば毎回書く必要がなくなります。

- **役割**（原則3）: 「あなたは当社の○○担当です」
- **出力形式**（原則4の一部）: 「回答は常に箇条書きで、結論を先に書いてください」
- **背景情報**（原則1の一部）: 「当社は従業員100名のITサービス会社で...」

カスタムインストラクションの例:

```
あなたは当社（株式会社テック・イノベーション、IT人材派遣業、
従業員120名）の営業企画チームの一員です。

回答のルール:
- 日本語で、ビジネス文書として適切なトーンで書いてください
- 結論を先に述べ、その後に根拠を示してください
- 箇条書きを活用し、1項目60字以内で書いてください
- 専門用語を使う場合は、括弧内に簡単な説明を添えてください
```

こう設定しておけば、日々の会話では「先月の営業成績のレポートをまとめてください」と一言頼むだけで、会社の文脈に合ったレポートが返ってきます。5原則を毎回全部書かなくても、Projectsが肩代わりしてくれるわけです。


## 6.8 ハンズオン: 3つのプロンプトを改善しよう

ここまでの5原則を実践してみましょう。以下の3つの「Before」プロンプトを、5原則を使って「After」に改善してみてください。まず自分で書いてみてから、改善例と見比べてみましょう。

---

### 課題1: 営業メールの作成

**Before**:

```
営業メールを書いてください。新製品の紹介です。
```

まず、この指示に足りない情報を考えてみてください。相手は誰でしょうか。製品はどんなものでしょうか。メールの目的は何でしょうか。

**After（改善例）**:

```
以下の条件で、営業メールのドラフトを書いてください。

あなたは中堅SaaS企業の法人営業担当者です。

<製品情報>
製品名: タスクボードPro
概要: チーム向けのプロジェクト管理ツール
特徴: AIが自動でタスクの優先順位を提案する機能
</製品情報>

<メールの条件>
- 送信先: 以前展示会で名刺交換した製造業のIT部門マネージャー
- 目的: 無料トライアルへの申し込みを促す
- トーン: 押し売り感がなく、相手の課題に寄り添う
```

## 6.9 まとめ

この章では、Claudeから高品質な回答を引き出す5つの原則を学びました。

- **原則1: 具体的に伝える** --- 背景・目的・読み手・成功条件の4つを明示する。曖昧な依頼は曖昧な結果しか生まない
- **原則2: お手本を見せる** --- 過去の成果物や理想の形式を1つ添えるだけで、出力の品質と一貫性が劇的に安定する
- **原則3: 役割を与える** --- 「あなたは○○の専門家です」と具体的に設定するほど、回答の深さと的確さが増す
- **原則4: 構造を与える** --- 箇条書き、見出し、カッコ（XMLタグ）で情報を整理して渡す。特にClaudeはこの構造化された指示への反応が良い
- **原則5: 段階的に進める** --- 大きなタスクは分割して、各ステップの品質を確認しながら進める。一発で完璧を求めない

そして、これらの原則を毎回手書きする必要はありません。Projectsのカスタムインストラクションに定型的な指示を設定しておけば、日々のやり取りは簡潔な一言で済みます。

:::message
**コラム: Claudeは優秀な新入社員**

Claudeとのコミュニケーションに迷ったとき、こう考えてみてください。Claudeは「とても優秀だけど、あなたの会社のことをまだ知らない新入社員」です。

能力は高い。言語力もある。指示されたことは丁寧にこなす。でも、あなたの会社の事業内容、部署の力関係、取引先との歴史、暗黙の了解---そういった「文脈」は一切知りません。

だから、人間の同僚なら「言わなくてもわかるだろう」と省略する情報も、Claudeには丁寧に伝える必要があります。逆に言えば、丁寧に伝えさえすれば、新入社員離れした高品質なアウトプットを返してくれます。

この章で紹介した5原則は、すべて「優秀な新入社員に仕事を頼むときの心がけ」そのものです。面倒に感じるかもしれませんが、慣れれば30秒で書ける指示が、30分の手戻りを防いでくれます。
:::

> **次の章では**: 5原則を実際のビジネス文書に応用します。企画書、提案書、報告書---日常的に作成するドキュメントを、Claudeとの3ステップ・ワークフローで劇的に効率化する方法を学びましょう。
