# 第7章: ドキュメント作成術 --- 企画書・提案書・報告書を10倍速で

金曜日の夕方、あなたは来週の部長会議に向けた企画書の作成を任されました。テーマは「社内DXの推進計画」。Wordを開き、白い画面を前に指が止まる。何から書き始めればいいのか。構成はどうする。データはどこから持ってくる。気がつけば30分経っていて、まだ1行も書けていない---。

この「ブランクページ恐怖症」は、多くのビジネスパーソンが経験する悩みです。

この章では、前章で学んだ5原則を実践に応用し、企画書・提案書・報告書といったビジネス文書を**Claudeとの3ステップ・ワークフロー**で効率的に作成する方法を紹介します。ゼロから1人で書く時代は終わりました。まずClaudeに骨格を作らせ、対話しながら仕上げていく。この方法を身につければ、文書作成にかかる時間を劇的に短縮できます。


## 7.1 「ブランクページ恐怖症」からの解放

ビジネス文書の作成で最も時間がかかるのは、実は「書く」工程ではありません。**「何をどの順番で書くか」を決める構成の段階**です。

頭の中に伝えたいことはぼんやりとある。しかし、それをどう並べれば読み手に伝わるのか。結論を先にすべきか、背景から丁寧に説明すべきか。データはどこに入れるか。悩んでいるうちに時間だけが過ぎていきます。

ここで発想を転換しましょう。**最初の一歩はClaudeに任せるのです。**

白紙の画面に向き合うのではなく、Claudeに「まず構成案を出して」と頼む。出てきた構成案を見れば、「ああ、この順番がいいな」「この項目は要らないな」「ここにデータを足そう」と、判断を下せます。ゼロから考えるのと、たたき台を見て判断するのとでは、脳の負荷がまったく違います。

これが本章で紹介する「3ステップ・ワークフロー」の核心です。

```
ステップ1: 骨格生成  → Claudeに構成案を複数出させる
ステップ2: 本文執筆  → 選んだ構成で各セクションを書かせる
ステップ3: 推敲・洗練 → トーン調整やデータの追加で仕上げる
```

人間がやるのは「どの構成がいいか選ぶ」「方向性を判断する」「最終チェックをする」という**判断と仕上げ**の部分だけです。文章を生み出す作業はClaudeに任せ、あなたは監督とディレクターに徹する。この役割分担が、文書作成を10倍速にする鍵です。


## 7.2 3ステップ・ワークフローの実践

それでは、具体的なプロンプトとともに3つのステップを見ていきましょう。お題は「社内向けDX推進の企画書」です。

### ステップ1: 骨格生成 --- 構成案を複数パターン出させる

最初のステップでは、Claudeに構成案を複数パターン出してもらいます。前章の原則1（具体的に伝える）と原則4（構造を与える）を使い、条件を明確に伝えましょう。

```
以下の条件で、社内DX推進の企画書の構成案を3パターン出してください。

<背景>
当社は従業員200名の中堅メーカーです。
現在、受注管理・在庫管理・日報をすべてExcelで運用しており、
月末の集計作業に各部署で合計40時間以上かかっています。
</背景>

<条件>
- 読み手: 経営会議のメンバー（社長、取締役3名）
- 目的: DX推進プロジェクトの承認を得る
- 分量: A4で3〜4ページ
- 予算規模: 年間500万円以内
</条件>

各パターンに「どんな読み手に刺さりやすいか」を1行で添えてください。
```

Claudeは3つの異なる切り口で構成案を提示してくれます。たとえば、「コスト削減を前面に出すパターン」「競合との差を強調するパターン」「現場の声を起点にするパターン」といった形です。

ここであなたがやるのは、**3つの中からベストを選ぶ**こと。あるいは「パターン1の冒頭にパターン3の現場の声を組み合わせて」と指示を出して、いいとこ取りをすることもできます。

:::message
**ポイント**: 構成案は必ず複数パターン出させましょう。1パターンだけだと「これでいいのか？」と迷いが生じますが、3つ並べると「この中ならこれが一番いい」と判断しやすくなります。選択肢があることで、逆に決断が速くなるのです。
:::

### ステップ2: 本文執筆 --- セクションごとに書かせる

構成が決まったら、本文を書いてもらいます。ここでは前章の原則5（段階的に進める）が重要です。「企画書を全部一気に書いて」ではなく、セクションごとに依頼しましょう。

```
パターン1の構成で企画書の本文を書いてください。

各セクションを300〜500字で書いてください。
読み手は数字を重視する経営層です。
以下の点を意識してください。
- 結論を各セクションの冒頭に書く
- 定量的なデータや数字を根拠として含める
- 専門用語は括弧内に簡単な説明を添える

まずセクション1（現状の課題）とセクション2（提案内容）を
書いてください。残りのセクションは次のステップでお願いします。
```

一度にすべてを書かせるのではなく、2セクションずつ進めるのがコツです。各セクションの出力を確認し、「もう少し具体的に」「数字を追加して」とフィードバックしてから次のセクションに進むことで、全体の品質を維持できます。

### ステップ3: 推敲・洗練 --- トーンと説得力を磨く

本文が一通り出来上がったら、最後は推敲です。ここが**人間の腕の見せどころ**です。Claudeの出力を読み、「ここは弱いな」「ここはもっとデータで裏付けたいな」と感じた部分を具体的に指示して磨き上げます。

```
企画書全体を以下の観点でブラッシュアップしてください。

1. 冒頭のサマリー: 「なぜ今やるべきか」の緊急性を強調する
2. コスト分析: 「投資回収期間は18か月」という数字を追加して
   根拠とともに説明する
3. トーン: 全体をよりフォーマルに。
   経営会議の場にふさわしい格調を持たせる
4. 結論: 「承認いただきたい事項」を明確に3点にまとめる
```

推敲の段階では、原則2（お手本を見せる）も効果的です。たとえば「過去に承認された企画書」があれば、そのテキストを貼り付けて「このトーンに合わせてください」と依頼すると、社内のお作法に沿った文体に調整してくれます。

---

この3ステップの全体像を図にすると、次のようになります。

```
┌──────────────────────────────────────────────┐
│  ステップ1: 骨格生成                          │
│  あなた: 条件を伝える                         │
│  Claude: 構成案を3パターン提示                 │
│  あなた: ベストを選ぶ（または組み合わせる）     │
├──────────────────────────────────────────────┤
│  ステップ2: 本文執筆                          │
│  あなた: セクションごとに依頼                  │
│  Claude: 各セクションの本文を生成              │
│  あなた: 都度確認し、方向修正                  │
├──────────────────────────────────────────────┤
│  ステップ3: 推敲・洗練                        │
│  あなた: 改善ポイントを具体的に指示            │
│  Claude: トーン調整、データ追加、表現修正      │
│  あなた: 最終チェックして完成                  │
└──────────────────────────────────────────────┘
```

ゼロから1人で企画書を書くと2〜3時間かかる作業が、この3ステップなら30分程度で初稿が完成します。もちろん、最終的な確認と微調整は人間がやりますが、「白紙から悩む時間」がほぼゼロになるのは大きな変化です。


## 7.3 文書タイプ別プロンプトテンプレート

3ステップ・ワークフローの骨格がわかったところで、よく作成するビジネス文書ごとのプロンプトテンプレートを紹介します。ステップ1（骨格生成）用のプロンプトです。コピーして、`[ ]` 内を自分の状況に書き換えるだけで使えます。

### 企画書

```
以下の条件で、[テーマ]の企画書の構成案を3パターン出してください。

<背景>
[プロジェクトの背景や現状の課題]
</背景>

<条件>
- 読み手: [誰が読むか（役職・立場）]
- 目的: [この企画書で何を達成したいか]
- 分量: [A4で何ページ、または何字程度]
- 予算: [概算予算があれば]
</条件>

各パターンの特徴を1行で添えてください。
```

### 提案書（顧客向け）

```
あなたは[業界]で10年の経験がある法人営業担当者です。

以下の条件で、顧客向け提案書のドラフトを作成してください。

<顧客情報>
- 企業名: [顧客の業種・規模]
- 担当者: [役職・立場]
- 課題: [先方が抱えている課題]
</顧客情報>

<提案内容>
- 提案するサービス/製品: [概要]
- 差別化ポイント: [競合との違い]
- 想定効果: [導入後に期待される成果]
</提案内容>

<出力形式>
1. エグゼクティブサマリー（3行以内）
2. 課題の整理
3. 提案内容
4. 期待される効果（定量的に）
5. 費用とスケジュール
6. 次のステップ
</出力形式>
```

### 週次報告書

```
以下の情報を、週次報告書のフォーマットにまとめてください。

<今週の実績>
[箇条書きで実績を列挙]
</今週の実績>

<来週の予定>
[箇条書きで予定を列挙]
</来週の予定>

<課題・懸念事項>
[あれば記載]
</課題・懸念事項>

フォーマット:
- 冒頭に「今週のハイライト」を1〜2行で記載
- 実績は達成度（%）や数字を含める
- 課題には対応策も添える
- 全体で400字以内
```

### 議事録

```
以下の会議メモを、正式な議事録にまとめてください。

<会議メモ>
[手書きのメモや走り書きをそのまま貼り付け]
</会議メモ>

出力形式:
- 件名 / 日時 / 参加者
- 議題ごとに「決定事項」と「アクションアイテム（担当者・期限）」を明記
- 次回予定
```

:::message
**議事録のコツ**: メモは綺麗に整理してから渡す必要はありません。「佐藤さんが予算の話、200万、高橋反対、結局300万で折り合い」のような走り書きでも、Claudeは文脈を読み取って整った議事録に仕上げてくれます。完璧なメモを取ることにエネルギーを使うより、会議の議論に集中し、メモの整理はClaudeに任せるほうが効率的です。
:::

### プレスリリース

```
あなたは大手企業の広報部で5年の経験がある担当者です。

以下の情報をもとに、プレスリリースのドラフトを作成してください。

<発表内容>
- 何を発表するか: [新サービス/業務提携/受賞 等]
- 発表日: [日付]
- 要点: [3つ以内で]
</発表内容>

<条件>
- トーン: 客観的かつ格調高い（広報文書として適切な表現で）
- 分量: 800〜1,200字
- 構成: タイトル → リード文 → 本文 → 会社概要
- 引用コメント: [役職名]のコメントを1つ含める
</条件>
```

これらのテンプレートは、前章で学んだ5原則がすべて組み込まれています。原則1（具体的に伝える）で条件を明示し、原則3（役割を与える）で専門家の視点を引き出し、原則4（構造を与える）でXMLタグと出力形式を指定しています。テンプレートを使うだけで、5原則を自然に実践できるわけです。


## 7.4 Projectsで「文書作成の専門家」を常駐させる

3ステップ・ワークフローとテンプレートだけでも十分効率化できますが、第3章で学んだProjectsを組み合わせると、さらに強力になります。

たとえば、あなたの会社には「文書のトーンやフォーマットのルール」があるはずです。ブランドガイドライン、社内の文書テンプレート、過去に承認された企画書。これらをProjectsに登録しておけば、毎回「うちの会社ではこういうトーンで...」と説明しなくても、Claudeが自動的にそのスタイルに合わせてくれます。

### おすすめの設定例

**プロジェクト名**: 「ビジネス文書アシスタント」

**ナレッジベースに登録する資料**:
- ブランドガイドライン（トーン&マナーの指針）
- 社内で高評価だった企画書・提案書（2〜3本）
- 文書テンプレート（企画書・報告書のフォーマット）
- 会社概要・事業内容の説明資料

**カスタムインストラクション**:

```
あなたは当社（株式会社○○、業種: ○○、従業員: ○○名）の
ビジネス文書作成を支援する専門アシスタントです。

登録されている資料のトーンとフォーマットに合わせて文書を作成してください。

回答のルール:
- 結論を先に述べ、根拠を後に示す「結論ファースト」で書く
- 1文は60字以内、1段落は4〜6文で区切る
- 数字やデータを積極的に使い、主張に根拠を持たせる
- 社内用語は登録資料に準拠する

文書作成時の注意:
- 企画書や提案書は、登録されている過去の成功事例のフォーマットに合わせる
- ブランドガイドラインのトーンを厳守する
- 不確かな数字やデータは「要確認」と注記する
```

この設定をしておけば、日々の文書作成は驚くほど簡潔な指示で済みます。

```
来月のマーケティング施策の企画書を書いてください。
テーマはSNS広告の強化で、予算は月額50万円です。
```

たったこれだけの指示でも、Claudeは登録されたブランドガイドラインのトーンで、過去の企画書のフォーマットに合わせた文書を作成してくれます。5原則の「背景」「役割」「出力形式」はProjectsが肩代わりしてくれるからです。

:::message
**トーン統一の威力**: 10人のチームで全員がこのProjectsを共有すれば、誰が書いても同じトーンの文書が出来上がります。「人によって文体がバラバラ」「新人の文書だけ浮いている」という問題が解消されます。Teamプランを利用すれば、この共有が簡単に実現できます。
:::


## 7.5 Artifactsで「その場で完成」を体験する

第4章で学んだArtifactsも、文書作成と相性抜群です。通常のチャットでは、Claudeの回答が会話ウィンドウに流れていきますが、Artifactsを使えば、文書が**独立したウィンドウで完成形として表示**されます。

これの何が嬉しいかというと、**全体像を見ながら修正指示が出せる**点です。

たとえば企画書のドラフトをArtifactとして生成すると、右側のウィンドウに見出し・箇条書き・表が整形された状態で表示されます。その全体像を眺めながら、「第2セクションの説明が薄いので、具体例を追加して」「冒頭のサマリーをもっと力強く」と修正を重ねていけます。

### Artifactsを使った文書作成の流れ

```
ステップ1: 「○○の企画書をArtifactとして作成してください」
  → 右側ウィンドウに企画書が表示される

ステップ2: 全体を眺めて修正点を指摘
  → 「セクション3にグラフを追加してください」
  → Artifactが即座に更新される

ステップ3: 仕上がったらコピーまたはダウンロード
  → Wordやメールに貼り付けて提出
```

Artifactsが特に威力を発揮するのは、**図やグラフを含む文書**の作成です。たとえば「プロジェクトのスケジュールをガントチャート風に図示して」と頼めば、Mermaidダイアグラムとして視覚的なスケジュール表が生成されます。「予算の配分を円グラフにして」と頼めば、インタラクティブなグラフが出来上がります。テキストだけでなく、ビジュアル要素も含めた文書が対話だけで完成するのです。


## 7.6 ハンズオン: 企画書を3ステップで作成する

ここまでの内容を実践してみましょう。所要時間は15分程度です。

### お題

あなた自身の業務に関連する企画書を1つ作成してください。テーマが思いつかない場合は、以下のお題を使ってください。

```
お題: 「社内の会議時間を30%削減するための改善提案書」
```

### 実践手順

**ステップ1: 骨格生成（3分）**

claude.aiで新しいチャットを開き、以下を入力してください。

```
以下の条件で、「社内の会議時間を30%削減する改善提案書」の
構成案を3パターン出してください。

<背景>
当社では週平均12時間が会議に費やされており、
社員アンケートで「会議が多すぎる」が不満の第1位でした。
</背景>

<条件>
- 読み手: 総務部長（業務効率化に関心が高い）
- 目的: 改善施策の承認を得る
- 分量: A4で2ページ以内
</条件>

各パターンの特徴を1行で添えてください。
```

3つの構成案が返ってきたら、最も良いと思うものを選びます。

**ステップ2: 本文執筆（5分）**

選んだパターンの番号を指定して、本文を依頼します。

```
パターン[番号]で企画書の本文を書いてください。
各セクション300〜500字で、数字やデータを根拠として含めてください。
読み手の総務部長は「具体的な効果」を重視する方です。
```

出力された本文を読んで、気になる点があれば修正を依頼します。

**ステップ3: 推敲（5分）**

最後に、全体を磨き上げます。

```
この企画書を以下の観点でブラッシュアップしてください。
- 冒頭のサマリーを「今すぐやるべき理由」が伝わる表現に
- 具体的な削減策を3つに絞り、優先順位をつける
- 最後に「次のアクション」を明記する
```

完成した企画書をコピーして、WordやGoogleドキュメントに貼り付ければ、あとは細かな体裁を整えるだけです。

---

いかがでしょうか。白紙から悩み続ける従来の方法と比べて、「まず構成案を見る → 選ぶ → 書かせる → 磨く」というプロセスの速さを実感いただけたのではないでしょうか。


## 7.7 ワンランク上のテクニック: 既存文書のリライト

新規作成だけでなく、**既存の文書を改善する**場面でもClaudeは大いに活躍します。

たとえば、こんな場面はないでしょうか。

- 部下が書いた報告書の文章を直したいが、赤入れに時間がかかる
- 過去の提案書を別の顧客向けにカスタマイズしたい
- 日本語の社内文書を英語に翻訳しつつ、フォーマルな表現に整えたい

こうした場面では、原文を貼り付けて改善ポイントを指示するだけで済みます。

**報告書のリライト例**:

```
以下の週次報告書を、より読みやすくリライトしてください。

<原文>
今週は色々やりました。A社の件が進んで、来週には契約できそうです。
B社は少し問題があります。予算がオーバーしているので相談が必要です。
あと新しいリードが3件入りました。
</原文>

<改善ポイント>
- 各項目を「進捗」「課題」「新規」に分類する
- 数字や期限を明確にする
- 上司がすぐに判断できる形式にする
</改善ポイント>
```

Claudeは原文の内容を保ちつつ、構造化された読みやすい報告書に変換してくれます。部下の文章をゼロから書き直すのではなく、「整えて」と頼むだけで済む。管理職にとって、これは大きな時間の節約です。


## 7.8 コラム: 人間の仕事は「判断」と「仕上げ」

:::message
**コラム: AIが書いた文書をそのまま出さない勇気**

この章を通じて、Claudeがいかに高品質な文書を生成できるかを見てきました。しかし、ここで1つ、とても大切なことをお伝えしたいのです。

**Claudeが書いた文書を、そのまま提出してはいけません。**

なぜでしょうか。理由は3つあります。

第一に、**事実の正確性**です。Claudeは説得力のある文章を書きますが、具体的な数字やデータを「それっぽく」生成することがあります。「市場規模は約3,000億円」と書かれていても、その数字が正しい保証はありません。数字やデータは必ず自分で裏取りしてください。

第二に、**社内文脈の反映**です。Claudeはあなたの会社の内部事情を完全には理解していません。「先月の部長会議で○○が議論された」「この顧客には過去にトラブルがあった」といった文脈は、人間にしか判断できません。

第三に、**あなた自身の言葉**であること。特に企画書や提案書は、提出者の「思い」や「覚悟」が問われる文書です。Claudeが作った骨格に、あなた自身の考えや経験を一言でも加えてください。それだけで、文書に命が宿ります。

AIの役割は「たたき台を高速で作ること」です。そして人間の役割は「判断すること」と「仕上げること」。この役割分担を間違えなければ、AIは最高の仕事のパートナーになります。

具体的なチェックリストを挙げておきます。Claudeの出力を提出する前に、以下を確認してください。

- [ ] 数字やデータの裏取りをしたか
- [ ] 社内の文脈や背景が正しく反映されているか
- [ ] 読み手に合ったトーンになっているか
- [ ] 自分の意見や判断が文書に含まれているか
- [ ] 固有名詞（人名・社名・製品名）に誤りはないか
:::


## 7.9 まとめ

この章では、前章の5原則をビジネス文書の作成に応用し、Claudeとの3ステップ・ワークフローで効率的に文書を仕上げる方法を学びました。

- **「ブランクページ恐怖症」の解消**: ゼロから書くのではなく、まずClaudeに骨格を作らせる。たたき台があれば人間は「判断」に集中できる
- **3ステップ・ワークフロー**: (1)骨格生成（構成案を複数パターン出させる） → (2)本文執筆（セクションごとに段階的に書かせる） → (3)推敲・洗練（トーン調整・データ追加で仕上げる）
- **文書タイプ別テンプレート**: 企画書、提案書、週次報告書、議事録、プレスリリースのプロンプトテンプレートをそのまま活用できる。5原則が自然に組み込まれている
- **Projectsで専門家を常駐**: ブランドガイドラインや過去の成功事例をProjectsに登録すれば、簡潔な指示だけでトーン統一の文書が量産できる
- **Artifactsで完成形を直接生成**: 右側ウィンドウで全体像を見ながら修正を重ね、図やグラフも含めた文書をその場で仕上げる
- **人間の仕事は「判断」と「仕上げ」**: 数字の裏取り、社内文脈の反映、自分の言葉を添えること。AIの出力をそのまま提出しない

> **次の章では**: 文書作成の次に時間を取られがちな「情報整理」に取り組みます。会議メモの要約、リサーチ結果の整理、学習ノートの作成---散在する情報をClaudeで一元管理し、ナレッジとして蓄積・再利用する方法を学びましょう。
