# 第8章: 情報整理術 --- 会議・調査・学習を一元管理する

月曜日の朝、あなたはデスクに座り、先週の振り返りをしようとしています。金曜日の顧客ミーティングで何が決まったか。木曜日に読んだ業界レポートの要点は何だったか。水曜日のチーム会議で誰がどのタスクを引き受けたか。Slackのスレッドを遡り、手書きのメモを探し、Googleドライブのどこかにあるはずの資料を検索する。気がつけば30分が過ぎて、まだ何も「整理」できていない---。

前章では、Claudeとの3ステップ・ワークフローでビジネス文書を効率的に「生成」する方法を学びました。この章では視点を変えて、**散在する情報を「整理」し、ナレッジとして「蓄積・再利用」する**方法を紹介します。会議メモ、調査資料、学習ノート。日々流れていく情報を、Claudeの力でストック情報に変えていきましょう。


## 8.1 「情報の洪水」問題

現代のビジネスパーソンが1日に処理する情報量は膨大です。会議メモ、メール、Slackメッセージ、調査資料、業界ニュース、社内Wiki。これらの情報は異なるツールに散在し、必要なときに見つからないという問題を引き起こしています。

情報が多いこと自体は悪くありません。問題は、**情報が整理されないまま流れていくこと**です。

たとえば、こんな経験はないでしょうか。

- 先週の会議で何が決まったか思い出せない
- 1か月前に読んだレポートの重要な数字がどこにもない
- 同じ情報を何度も最初から調べ直している
- 調査結果をまとめたはずのファイルが見つからない

これらは「情報を受け取っているのに活用できていない」状態です。情報のインプットは十分なのに、整理と蓄積のプロセスが欠けているのです。

ここにClaudeを組み込むと、状況が一変します。Claudeは大量のテキストを瞬時に処理し、要約・構造化・分類する能力に長けています。あなたが「読む」「聞く」「調べる」で得た情報を、Claudeで「整理する」「蓄積する」「再利用する」に変換する。これが本章のテーマです。

```
情報の流れ（Before）:
  会議メモ → 書きっぱなし → 忘れる
  調査資料 → 読みっぱなし → 探せない
  学習内容 → 聞きっぱなし → 定着しない

情報の流れ（After）:
  会議メモ → Claude要約 → アクションアイテム → 実行・追跡
  調査資料 → Claude分析 → 重要ポイント → Projectsに蓄積
  学習内容 → Claude対話 → 理解の深掘り → ナレッジとして保存
```

それでは、3つの代表的なワークフローを順に見ていきましょう。


## 8.2 ワークフロー1: 会議の情報整理

ビジネスパーソンが最も頻繁に「情報を取りこぼす」場面は、会議です。議論に集中していると、メモを取る手が追いつかない。走り書きのメモを見返しても、文脈が思い出せない。結果として、「あの件、どうなったんだっけ？」が頻発します。

Claudeを使った会議情報の整理フローは、次の4ステップです。

```
ステップ1: 会議メモまたは文字起こしを用意する
ステップ2: Claudeに要約を依頼する
ステップ3: アクションアイテムを抽出する
ステップ4: フォローアップ文を作成する
```

### ステップ1: 会議メモを用意する

メモは完璧でなくて構いません。前章のコラムでも触れましたが、走り書きレベルで十分です。最近はZoomやTeamsの文字起こし機能も普及しています。音声文字起こしツールの出力をそのまま使うことも可能です。

### ステップ2: 要約を依頼する

メモや文字起こしデータをClaudeに渡し、構造化された要約を依頼します。

```
以下の会議メモを、構造化された議事録にまとめてください。

<会議メモ>
2/17 14時 営業部定例
参加: 佐藤部長、田中、鈴木、高橋
Q1の売上状況、佐藤さん報告。目標1.2億に対して現時点で8500万。
達成率71%。残り2ヶ月で3500万必要。
田中さんからA社案件の進捗。提案書出した、来週返事もらえそう。
金額は1200万。
鈴木さん、B社は厳しい。競合が値下げしてきた。
対策として田中と鈴木で共同提案を検討する方向に。
高橋さん新規リード5件獲得。来月中にアポ取る予定。
次回3/3 14時
</会議メモ>

<出力形式>
- 件名 / 日時 / 参加者
- 議題ごとに決定事項とアクションアイテム（担当者・期限）を明記
- 全体のサマリーを冒頭に2行で記載
</出力形式>
```

Claudeは走り書きのメモから文脈を読み取り、整った議事録を作成してくれます。第6章の原則4（構造を与える）で学んだXMLタグを活用して、入力と出力の形式を明確にしているのがポイントです。

### ステップ3: アクションアイテムを抽出する

議事録ができたら、続けてアクションアイテムだけを抽出します。

```
この議事録から、アクションアイテムを一覧にしてください。

形式:
- 担当者 | タスク内容 | 期限 | 優先度（高/中/低）
```

Claudeは議事録の内容から、誰が何をいつまでにやるべきかを整理してくれます。「田中 | A社からの返答をフォローアップ | 来週中 | 高」のように、表形式で一覧化されるため、タスク管理ツールにそのまま転記できます。

### ステップ4: フォローアップ文を作成する

会議後に参加者へ共有するフォローアップメールも、そのまま続けて依頼できます。

```
この議事録をもとに、参加者への共有メールを作成してください。
決定事項とアクションアイテムを簡潔にまとめ、
次回会議の日時を記載してください。
トーンは社内向けのカジュアルなものでお願いします。
```

会議メモの投入から、議事録の完成、アクション抽出、フォローアップ文の作成まで、**すべて1つのチャットの中で完結**します。以前なら30分以上かかっていた作業が、5分ほどで終わります。

:::message
**音声文字起こしとの組み合わせ**: ZoomやTeamsの文字起こし機能、あるいはOtterやNottaなどの専用ツールで音声をテキスト化し、その出力をClaudeに渡すのが最も効率的です。文字起こしデータは冗長で読みにくいことが多いですが、Claudeはそこから要点を正確に拾い上げてくれます。「メモを取る」作業そのものから解放されるのは大きなメリットです。
:::


## 8.3 ワークフロー2: リサーチ・調査の整理

業務で調査やリサーチを行う場面は多くあります。競合分析、市場調査、技術調査、新しい制度の確認。しかし、調べた結果を「読んだだけ」で終わらせてしまうと、数週間後には内容を忘れ、同じことを一から調べ直すことになります。

Claudeを使ったリサーチ整理のワークフローは、大きく2つのパターンがあります。

### パターン1: 長文資料の要約と重要ポイント抽出

50ページのPDFレポートや、複数の記事をまとめて読む必要がある場面。すべてを精読する時間はありません。まずClaudeに要約してもらい、重要なポイントを把握してから、深掘りすべき箇所を絞り込みましょう。

```
以下の業界レポートを読んで、次の形式で要約してください。

<レポート>
（PDFの内容、またはテキストを貼り付け）
</レポート>

<出力形式>
1. 全体サマリー（3行以内）
2. 重要な発見トップ5（各2行で、根拠となる数字を含める）
3. 自社に関係しそうなポイント（当社はIT人材派遣業、従業員120名）
4. さらに調査が必要な点
</出力形式>
```

ここで第6章の原則1（具体的に伝える）が活きます。「要約して」だけでなく、「自社に関係するポイント」を指定することで、汎用的な要約ではなく、**あなたの業務に即した要約**が返ってきます。

### パターン2: 複数資料の横断分析

調査では、1つの資料だけでなく複数のソースを比較・統合することが求められます。Claudeの200Kトークン（約500ページ相当）の処理能力が真価を発揮するのはここです。

```
以下の3つの記事を読んで、横断的に分析してください。

<記事1>
（テキストを貼り付け）
</記事1>

<記事2>
（テキストを貼り付け）
</記事2>

<記事3>
（テキストを貼り付け）
</記事3>

分析してほしいこと:
1. 3つの記事に共通するトレンドを3つ挙げてください
2. 記事間で矛盾している点があれば指摘してください
3. これらの情報を総合すると、当社が取るべきアクションは何ですか
```

人間が3つの記事を精読し、共通点と相違点を分析するには1時間以上かかるかもしれません。Claudeなら数十秒で横断分析を返してくれます。もちろん、その分析が正しいかどうかの判断は人間の仕事です。しかし、「分析の出発点」を瞬時に得られることの価値は計り知れません。

:::message
**調査結果をProjectsに蓄積する**: 調査で得た要約や分析結果は、その場限りにせず、第3章で学んだProjectsのナレッジベースに追加しましょう。たとえば「業界調査」というプロジェクトを作り、毎月の調査要約をテキストファイルにしてアップロードしていく。すると、Claudeは過去の調査結果を踏まえた回答ができるようになります。「先月のレポートと比較して変化した点は？」といった質問にも答えられるようになるのです。
:::


## 8.4 ワークフロー3: 学習・読書の効率化

ビジネス書や技術書を読む時間を確保するのは難しいものです。せっかく読んでも、1か月後には内容の大半を忘れてしまう。そんな経験をお持ちの方も多いのではないでしょうか。

Claudeを「読書の伴走者」として活用すると、学習の深さと定着率が大きく変わります。

### PDFをProjectsに登録して対話的に学ぶ

第3章で学んだProjectsの機能を使えば、書籍のPDFをナレッジベースに登録し、**対話形式で内容を深掘り**できます。

```
プロジェクト名: 「○○（書籍名）読書ノート」

カスタムインストラクション:
登録された書籍の内容について、わかりやすく解説してください。
質問に対しては、書籍の該当箇所を引用しながら回答してください。
専門用語は平易な言葉で言い換えてください。
```

このプロジェクトを作ったら、対話を通じて内容を深掘りしていきます。

```
質問例1: この本の主張を3行でまとめてください。

質問例2: 第3章の「両利きの経営」の概念を、
         具体的な企業の事例で説明してください。

質問例3: この本の内容を、当社（IT人材派遣業、従業員120名）の
         経営に当てはめると、どのような示唆がありますか？

質問例4: この本と、前に読んだドラッカーの考え方の
         共通点と相違点を教えてください。
```

ただ読むだけの受動的な学習と、対話で深掘りする能動的な学習では、理解の深さがまったく違います。「自分の業務に当てはめると？」という問いかけが、抽象的な知識を具体的な行動に変えてくれます。

### 学習ポイントのまとめ生成

書籍を読み終えたら（あるいは読みながら）、要点のまとめを生成してもらいましょう。

```
この書籍の内容を、以下の形式でまとめてください。

<出力形式>
1. 書籍の3行要約
2. 重要な概念トップ5（各概念を2〜3文で説明）
3. 明日から使えるアクション3つ（具体的な行動レベルで）
4. 印象的な引用・フレーズ3つ
</出力形式>
```

この「学習まとめ」をテキストファイルとして保存し、Projectsに追加していけば、**自分だけの読書データベース**が出来上がります。後から「マーケティング戦略について、過去に読んだ本ではどう書かれていた？」と質問すれば、複数の書籍を横断した回答が返ってきます。

:::message
**書籍PDFの注意点**: Projectsに登録するPDFは、テキストが埋め込まれたものが必要です（第3章参照）。スキャン画像のみのPDFでは、Claudeが内容を読み取れません。電子書籍（EPUB）をお持ちの場合は、そちらを登録するほうが確実です。また、著作権への配慮として、個人の学習目的の範囲で活用してください。
:::


## 8.5 Projectsをナレッジベースとして育てる

3つのワークフローに共通する重要なポイントがあります。それは、**整理した情報をProjectsに蓄積していく**という習慣です。

第3章では、Projectsを「AIに予備知識を与える部屋」として紹介しました。ここではさらに一歩進めて、Projectsを**「成長するナレッジベース」**として活用する方法を考えてみましょう。

### ナレッジベースの育て方

具体的な手順はシンプルです。

1. 会議の要約、調査のまとめ、学習ノートをテキストファイルにする
2. そのファイルをProjectsのナレッジベースに追加する
3. 新しい情報が入るたびに、ファイルを更新または追加する

たとえば「営業部門ナレッジ」というプロジェクトに、以下の資料を段階的に追加していくとします。

```
最初に登録:
  ・商品カタログ.pdf
  ・過去の提案書.pdf

1ヶ月目に追加:
  ・Q1営業会議の議事録まとめ.txt
  ・競合調査レポート要約.txt

2ヶ月目に追加:
  ・顧客フィードバック分析.txt
  ・業界トレンドまとめ.txt

3ヶ月目に追加:
  ・Q1の成功事例と失敗事例.txt
  ・新サービスの提案書ドラフト.txt
```

時間が経つほど、Claudeが参照できる情報が増えていきます。最初は「一般的な提案書のドラフト」しか書けなかったClaudeが、3ヶ月後には「この四半期の業界トレンドと、過去の成功事例を踏まえ、競合との差別化ポイントを含めた提案書」を書けるようになるのです。

### ナレッジベースのカスタムインストラクション例

ナレッジベースとして使うプロジェクトには、次のようなカスタムインストラクションが効果的です。

```
あなたは当社の業務アシスタントです。
登録されているナレッジベースの情報を最大限に活用して回答してください。

回答のルール:
- 過去の議事録やレポートに関連する情報がある場合は、
  必ず参照して回答してください
- 情報の鮮度を意識し、古い情報と新しい情報が矛盾する場合は
  新しい情報を優先してください
- ナレッジベースに該当する情報がない場合は、
  「登録されている資料には該当する情報がありません」と明示してください
- 回答の根拠となった資料名を示してください
```

:::message
**ナレッジの定期メンテナンス**: ナレッジベースは追加するだけでなく、定期的な整理も大切です。古くなった情報は削除するか、最新版に差し替えましょう。200Kトークンの容量は大きいですが、無限ではありません。「量より質」を意識し、本当に必要な情報を厳選することで、Claudeの回答品質はさらに高まります。
:::


## 8.6 ハンズオン: 会議メモをClaudeで整理する

ここまでの内容を実践してみましょう。所要時間は10分程度です。

### お題

最近参加した会議のメモを1つ用意してください。手書きのメモでも、テキストのメモでも構いません。適切なメモが手元にない場合は、以下のサンプルを使ってください。

```
サンプル会議メモ:

2/14 10時 マーケ部定例
参加 山田部長 木村 中村 小林
来月のキャンペーンについて。
木村さんからSNS広告の提案。Instagram中心で予算30万。
山田部長はTikTokも検討してほしいと。
中村さん、前回のキャンペーンの振り返り。CTR1.2%で業界平均以下。
クリエイティブが弱かったのではという分析。
小林さん、外部のデザイナーに依頼する案を提示。費用は10万追加。
結論として、Instagram+TikTokの2本立てで進める。
デザインは外部委託。木村が来週までに詳細プランを出す。
中村は過去データの詳細分析を来週中に。
次回2/28。
```

### 実践手順

**ステップ1: 要約と構造化（3分）**

claude.aiで新しいチャットを開き、以下を入力してください。

```
以下の会議メモを、構造化された議事録にまとめてください。

<会議メモ>
（ここに自分のメモ、またはサンプルを貼り付け）
</会議メモ>

<出力形式>
- 全体サマリー（2行以内）
- 件名 / 日時 / 参加者
- 議題ごとに「議論内容」「決定事項」「アクションアイテム（担当・期限）」
- 次回予定
</出力形式>
```

Claudeが整った議事録を返してくれます。走り書きのメモがどれだけ読みやすく変換されるか、確認してみてください。

**ステップ2: アクションアイテムの抽出（2分）**

続けて、同じチャットで以下を入力します。

```
この議事録から、アクションアイテムだけを一覧にしてください。
担当者 | タスク | 期限 | 優先度（高/中/低）の形式でお願いします。
```

表形式で整理されたアクションアイテムが返ってきます。このリストはそのまま、タスク管理ツールやチーム共有のメッセージに使えます。

**ステップ3: フォローアップメールの作成（3分）**

最後に、参加者への共有メールを作成してもらいます。

```
この議事録をもとに、参加者への共有メールを書いてください。
決定事項とアクションアイテムを箇条書きで簡潔にまとめてください。
社内メールなので、カジュアルなトーンでお願いします。
```

---

いかがでしょうか。会議メモの投入から、議事録の完成、アクション抽出、フォローアップ文の作成まで、1つのチャットの中でスムーズに完結する体験を実感いただけたのではないでしょうか。一度この流れに慣れると、手作業には戻れなくなるはずです。


## 8.7 コラム: フロー情報からストック情報へ

:::message
**コラム: 「一回読んで終わり」にしない情報活用**

ビジネスで扱う情報には、大きく分けて2つの種類があります。

**フロー情報**とは、流れていく情報です。日々のメール、Slackのメッセージ、会議の発言、ニュース記事。これらは「その場で消費される」性質を持っています。読んで、対応して、次に流れていく。

**ストック情報**とは、蓄積される情報です。マニュアル、データベース、過去の事例集、分析レポート。これらは「何度も参照される」性質を持っています。

多くのビジネスパーソンの悩みは、**フロー情報がフローのまま流れ去ってしまう**ことにあります。会議で良い議論をしても、メモが整理されなければ3日で忘れます。優れた記事を読んでも、要点をまとめなければ1か月後には内容が曖昧になります。

Claudeは、この「フローからストックへの変換装置」として機能します。

- 会議の発言（フロー）→ 構造化された議事録（ストック）
- 読んだ記事（フロー）→ 要点まとめ（ストック）
- 調査で得た知見（フロー）→ ナレッジベースの一部（ストック）

大切なのは、**情報に触れたその瞬間に、ストックに変換する習慣**を持つことです。「後で整理しよう」と思った情報は、たいてい整理されないまま忘れ去られます。会議が終わった直後にClaudeにメモを渡す。記事を読み終えた直後にClaudeに要約を頼む。このワンアクションを習慣にするだけで、あなたのナレッジは着実に積み上がっていきます。

情報を「受け取る力」は多くの人が持っています。しかし、情報を「蓄積して再利用する力」を持つ人は少数です。Claudeとの協働で、あなたはその少数の側に立つことができるのです。
:::


## 8.8 まとめ

この章では、散在する情報をClaudeで整理し、ナレッジとして蓄積・再利用する3つのワークフローを学びました。

- **「情報の洪水」問題の解決**: 会議メモ、調査資料、学習ノート---流れていく情報をClaudeで構造化し、活用可能な形に変換する
- **ワークフロー1: 会議の情報整理**: メモや文字起こし → 要約 → アクションアイテム抽出 → フォローアップ文作成。走り書きのメモから5分で議事録が完成する
- **ワークフロー2: リサーチ・調査**: 長文資料の要約と重要ポイント抽出、複数資料の横断分析。200Kトークンの処理能力を活かし、大量の情報を一度に分析できる
- **ワークフロー3: 学習・読書**: 書籍PDFをProjectsに登録し、対話形式で深掘り。受動的な読書を能動的な学習に変える
- **Projectsをナレッジベースとして育てる**: 整理した情報を逐次追加することで、時間とともにClaudeの回答品質が向上する。「成長するAIアシスタント」が手に入る
- **フロー情報からストック情報へ**: 情報に触れた瞬間にClaudeで整理する習慣が、ナレッジの蓄積と再利用の鍵

> **次の章では**: 情報整理と並んで日常業務の大きな時間を占める「メール・コミュニケーション」に取り組みます。相手の立場や場面に応じた文面を、Claudeの力で瞬時に作成する方法を学びましょう。
